召回是推荐系统链路中的第一个流程，目的是从几亿个 item 中选出几千个 item。进行召回的模型方法多种多样，包括但不仅限于基于统计学的、基于规则的和基于神经网络的。本章先从最基础的协同过滤开始介绍。

召回只求「别漏掉用户可能感兴趣的」，精度要求低、速度要求高。

## 1. 基于物品的协同过滤（ItemCF）

### 原理与实现

ItemCF 的基本思想：如果用户喜欢物品 i₁，而物品 i₁ 与物品 i₂ 相似，那么用户很可能喜欢物品 i₂。例如用户喜欢《笑傲江湖》，而《笑傲江湖》与《鹿鼎记》相似，就给用户推荐没看过的《鹿鼎记》。

根据该思想，ItemCF 的实现分为三步：

1. 基于转化流程中的动作，得到某用户对物品的兴趣分数 `like(user, item)`；
2. 离线计算物品之间的相似度 `sim(item, item)`；
3. 线上预估用户对候选物品的兴趣。

数值例子：

```
2×0.1 + 1×0.4 + 4×0.2 + 3×0.6 = 3.2
```

### 物品相似度

ItemCF 认为两个物品的**受众重合度越高，两个物品越相似**。所以物品相似度基于与两个物品交互的用户群体重合度计算：

1. 喜欢物品 i₁ 的用户集合记作 W₁，喜欢物品 i₂ 的记作 W₂；
2. 定义交集 V = W₁ ∩ W₂。不考虑喜欢程度时，相似度（Jaccard 风格的余弦）为：

```
sim(i₁, i₂) = |V| / sqrt(|W₁| · |W₂|)
```

3. 考虑用户对不同物品的喜欢程度对相似度的影响，得到常用的余弦相似度：

```
sim(i₁, i₂) = Σ_{v∈V} like(v,i₁)·like(v,i₂)
              / sqrt(Σ_{u∈W₁} like(u,i₁)² · Σ_{u∈W₂} like(u,i₂)²)
```

本质：把每个物品表示为一个稀疏向量（每个元素对应一个用户），相似度就是两个向量夹角的余弦。

### ItemCF 召回的完整流程

线上召回之前，需要先做离线计算、存储结果并建立索引：

1. **用户 → 物品**索引（用户 ID → (物品 ID，兴趣分数) 列表）
   - 记录每个用户最近点击、交互过的物品 ID
   - 给定任意用户 ID，可以找到该用户近期感兴趣的物品列表
2. **物品 → 物品**索引（物品 ID → 最相似的 k 个物品的 (ID，相似度)）
   - 计算物品之间的两两相似度
   - 对于每个物品，索引它最相似的 k 个物品

基于索引的线上召回：

1. 给定用户 ID，通过「用户 → 物品」索引找到用户近期感兴趣的物品列表（last-n）
2. 对 last-n 中每个物品，通过「物品 → 物品」索引找到最相似的 k 个物品（最多取回 nk 个）
3. 对取回的相似物品，用公式预估用户对每个物品的兴趣分数：

```
score(user, item) = Σ_{i∈用户交互过的物品} like(user, i) × sim(i, item)
```

4. 返回分数最高的 100 个物品作为召回结果

数值例子：n=200、k=10 → nk=2000 个候选，返回 Top 100。

> Tip：索引的意义在于**避免暴力枚举所有物品**。虽然离线计算量大，但有效减少了线上计算量。

## 2. Swing 召回通道

### ItemCF 的问题：小圈子

ItemCF 计算物品相似度基于用户群体重合度。如果重合的用户来自一个小圈子（比如某个微信群），受众完全不同的两个物品也容易被误判为相似（例：《某网站护肤品打折》和《字节裁员了》），实际落地效果较差。

### Swing 的思想

需要考虑用户之间的物品重合度，**降低小圈子的权重**，在 ItemCF 的基础上提出 Swing：

1. 用户 u_a 喜欢的物品集合记作 J_a，用户 u_b 的记作 J_b
2. 定义两个用户的重合度：`overlap(u_a, u_b) = |J_a ∩ J_b|`。重合度高则可能来自一个小圈子，计算物品相似度时要降低他们的权重
3. 定义交集 V = W₁ ∩ W₂（同时喜欢 i₁、i₂ 的用户），两个物品的相似度为：

```
sim(i₁, i₂) = Σ_{u_a∈V} Σ_{u_b∈V} 1 / (α + overlap(u_a, u_b))
```

其中 α 是超参数。该公式体现了：用户群体的重合度越大（越可能来自小圈子），他们对物品相似度的贡献越小。

> Swing 与 ItemCF 的唯一区别：**物品相似度的定义**。其余流程完全一样。

## 3. 基于用户的协同过滤（UserCF）

### 原理与实现

UserCF 的基本思想：如果用户 user 与用户 user′ 相似，而且 user′ 喜欢某物品，那么 user 很可能也喜欢该物品。例如有很多与我兴趣相似的网友，其中某个网友点赞、转发了一篇笔记，就给我推荐这篇没看过的笔记。

实现分三步：

1. 基于转化流程中的动作得到用户对某物品的兴趣分数 `like(user, item)`；
2. 离线计算用户之间的相似度 `sim(user, user)`；
3. 线上预估用户对候选物品的兴趣。

数值例子：

```
0.9×0 + 0.7×1 + 0.7×3 + 0.4×0 = 2.8
```

### 用户相似度

类似于 ItemCF，UserCF 认为两个用户喜欢的物品重合度越高越相似：

1. 用户 u₁ 喜欢的物品集合记作 J₁，用户 u₂ 的记作 J₂；
2. 定义交集 I = J₁ ∩ J₂，简单相似度为：

```
sim(u₁, u₂) = |I| / sqrt(|J₁| · |J₂|)
```

3. 这个公式等价于给交集里的每个物品权重 1，**没有区别对待冷门和热门物品**。但热门物品只占所有物品的很小部分，且很容易出现不同用户喜欢同一个热门物品，所以越热门的物品越无法反映用户的独特兴趣；
4. 为降低热门物品权重，相似度更新为：

```
sim(u₁, u₂) = Σ_{l∈I} 1/log(1 + n_l) / sqrt(|J₁| · |J₂|)
```

其中 n_l 是喜欢物品 l 的用户数量，反映物品的热门程度。对数里 +1 是为了让对数项恒为正、避免分母过小或为零（相似度值域为 [0,1]）。

### UserCF 召回的完整流程

离线建两个索引：

1. **用户 → 物品**索引：记录每个用户最近交互过的 n 个物品
2. **用户 → 用户**索引：计算用户两两相似度，每个用户索引最相似的 k 个用户

线上召回：

1. 给定用户 ID，通过「用户 → 用户」索引找到 top-k 相似用户
2. 对每个相似用户，通过「用户 → 物品」索引找到其近期感兴趣的物品列表（last-n，最多 nk 个）
3. 用公式预估用户对每个物品的兴趣分数：

```
score(user, item) = Σ sim(user, user′) × like(user′, item)
```

4. 返回分数最高的 100 个物品作为召回结果

> Tip：ItemCF 和 UserCF 的索引使用顺序不同。ItemCF：用户 ID → 感兴趣物品（用户→物品）→ 相似物品（物品→物品）；UserCF：用户 ID → 相似用户（用户→用户）→ 相似用户感兴趣的物品（用户→物品）。两者最后都用公式算兴趣分数排序。

## 4. 离散特征处理

在介绍矩阵补全之前，先看推荐系统中处理离散特征的常见方法：

1. **建立字典**：把离散特征的所有类别映射成序号（中国→1，美国→2……）
2. **向量化**：把序号映射成向量
   - **One-hot 编码**：序号 → 高维稀疏向量
   - **Embedding（嵌入）**：序号 → 低维稠密向量

离散特征举例：性别（2 类）、国籍（约 200 类）、英文单词（几万个）、物品 ID（几亿）、用户 ID（几亿）。

前面的 ItemCF/UserCF 在计算相似度时就是把用户和物品表示成稀疏向量。但实际应用中用户和物品数量极其巨大，过于稀疏的向量计算复杂、计算量过大、存储困难，所以 embedding 是业界常用的方式。TensorFlow、PyTorch 都提供 embedding 层，实现上就是「参数矩阵 × One-hot 向量」的查表。

- One-hot 维度 = 类别数量，类别太多时维度爆炸
- Embedding 参数 = 向量维度 × 类别数量
- 例：200 个国籍 × 4 维 = 800 个参数；10,000 部电影 × 16 维 = 160,000 个参数

## 5. 矩阵补全与最近邻查找

### 矩阵补全（Matrix Completion）

矩阵补全，顾名思义就是把一个含有缺失值的矩阵通过一定方法补全为完整矩阵。推荐系统里要补全的矩阵是「用户 × 物品」的兴趣分数矩阵：绿色位置是曝光过的物品（有分数），灰色位置没有曝光（分数缺失）。

模型基于 embedding 做推荐：

1. 用户 embedding 参数矩阵记作 A，第 u 号用户对应第 u 列，映射为向量 a_u；物品 embedding 矩阵记作 B，第 i 号物品对应第 i 列，映射为向量 b_i（两个 embedding 层**不共享参数**）
2. 内积 ⟨a_u, b_i⟩ 是用户 u 对物品 i 兴趣的预估值
3. 训练目标是学习矩阵 A 和 B，使预估值拟合真实观测的兴趣分数，求解最优化问题：

```
min_{A,B} Σ_{(u,i,y)∈Ω} (y − ⟨a_u, b_i⟩)²
```

训练数据集为 `(用户ID, 物品ID, 兴趣分数)` 的集合 Ω，分数由系统记录：曝光没点击 0 分，点击、点赞、收藏、转发各算 1 分（0~4 分）。

> 换句话说：用绿色位置（已曝光）的数据训练模型，再用模型预估灰色位置（未曝光）的兴趣分数，实现补全。

### 矩阵补全的三个缺点

1. **仅仅使用 ID 做 embedding**，没有考虑物品和用户的属性（类目、关键词、地理位置、作者信息、性别、年龄等）——双塔模型可以看作矩阵补全的升级版
2. **负样本选取方式不对**：把「曝光后没有点击交互」的物品当负样本是错误的（双塔模型章节会详讲）
3. **训练方法不对**：用内积不如用余弦相似度；用平方损失（回归）不如用交叉熵损失（分类）

### 线上服务与最近邻查找

训练完成后保存矩阵 A 和 B：A 的列存到 key-value 表（key 用户 ID，value 用户向量）；B 的存储和索引比较复杂。

线上召回流程：

1. 用用户 ID 查 key-value 表，得到用户向量 a
2. 最近邻查找：找内积最大的 k 个物品作为召回结果

Milvus、Faiss、HnswLib 等系统支持最近邻查找，衡量标准包括：**欧式距离最小（L2）、向量内积最大、向量夹角余弦最大**。

暴力枚举所有物品的时间复杂度正比于物品数量（几亿量级），实际落地很难应用，因此需要**近似最近邻查找（ANN）**来加速。

### 近似最近邻查找的思路（课程例子）

以余弦相似度为例：

1. 全部 n 个物品向量分布在一个空间里，把空间划分为 b 个小区域（余弦相似度对应扇形区域划分），每个区域用一个单位向量表示
2. 以区域表示向量为 key，该区域内所有物品（数量约 n/b）的列表为 value，得到 b 个索引
3. 线上召回时，先算用户向量 a 与全部 b 个区域向量的相似度，复杂度 O(b)
4. 找到相似度最高的区域，再算 a 与该区域内约 n/b 个物品向量的相似度，复杂度 O(n/b)
5. 选出最相似的 k 个物品作为召回结果

复杂度对比：暴力枚举 O(n)；两级查找 O(b + n/b)。把几亿个物品分到几万个区域、每个区域几万个物品，计算量远小于暴力枚举。

## 6. 双塔模型

### 模型介绍

矩阵补全存在诸多问题，业界提出落地有效的双塔模型：

```
用户侧：用户ID + 离散特征 + 连续特征 → 特征变换神经网络 → a
物品侧：物品ID + 离散特征 + 连续特征 → 特征变换神经网络 → b
兴趣预估值 = cos(a, b)
```

左右分别是用户塔和物品塔，充分使用用户和物品的多维特征属性，用**余弦相似度**替代内积预估兴趣。两个塔结构一致，只是特征变换方法和神经网络参数不同。

**后期融合 vs 前期融合**（重要）：

- 适用于**召回**的双塔模型是**后期融合**：先分别用神经网络生成用户、物品表征，再计算两个表征之间的相似度。这样物品向量可以离线算好，线上只算用户向量 + 最近邻检索
- **粗排、精排**需要使用**前期融合**：先拼接用户和物品的特征，再输入神经网络输出兴趣分数（concatenate 模型）。这种模型能利用用户—物品交叉特征，精度更高，但线上要逐物品过模型，**不适合召回**

### 三种训练方式

| 训练方法 | 选取样本 | 训练目标 | 损失函数 |
| --- | --- | --- | --- |
| Pointwise | 独立看待每个正负样本 | 把召回看作二元分类：正样本 cos→+1，负样本 cos→−1（正负比例约 1:2 或 1:3） | 交叉熵损失 |
| Pairwise | 每次取一个正样本 + 一个负样本 | 鼓励用户与正样本的余弦相似度大于与负样本的 | 合页损失（hinge） |
| Listwise | 每次取一个正样本 + 多个负样本 | 鼓励正样本相似度尽量大、每个负样本尽量小 | Sampled Softmax Loss |

记号：用户特征向量 a；正样本 b⁺；负样本 b⁻；多个负样本 b₁⁻…b_m⁻；cos 计算余弦相似度。

**Pairwise 的损失**：

希望 cos(a,b⁺) 大于 cos(a,b⁻)：

```
Triplet Hinge Loss:   L = max(0, cos(a,b⁻) + m − cos(a,b⁺))   （m 是 margin）
Triplet Logistic Loss: L = log(1 + exp(σ·(cos(a,b⁻) − cos(a,b⁺))))
```

正负物品塔共享参数。

**Listwise 的损失**：把 cos 值过 Softmax 变成概率 p，真实标签 y 中正样本为 1、负样本为 0，然后算交叉熵：

```
L = −log( exp(cos(a,b⁺)) / Σ_j exp(cos(a,b_j)) )
```

最后用梯度下降减小损失。

### 正负样本

**正样本**：曝光而且有点击的「用户—物品」二元组。

实际问题：少部分热门物品占据大部分点击，导致正样本大多是热门物品。解决：**过采样冷门物品**（一个样本出现多次），或**降采样热门物品**（丢弃一些样本）。

**负样本**需要合理且正确，按分类难度分为：

| 负样本类型 | 负样本来源 | 选取思想 |
| --- | --- | --- |
| 简单负样本 | 全体物品 | 未被召回的物品大概率不感兴趣，分类准确率高（简单）。被召回的只是很小一部分，所以未召回 ≈ 全体物品。**非均匀抽样**打压热门物品：抽样概率 ∝ 点击次数^0.75 |
| 简单负样本 | Batch 内负样本 | 一个 batch 有 n 个正样本（用户—物品对），任意用户和其他 n−1 个物品组成负样本，共 n(n−1) 个。物品出现在 batch 的概率 ∝ 点击次数，增大了热门物品成为负样本的概率，需要纠偏 |
| 困难负样本 | 被排序淘汰的物品 | 用户可能感兴趣但兴趣不够强的物品，分类比较困难 |
| 困难负样本 | 精排分数靠后的物品 | 用户可能感兴趣但精排分数靠后的物品，分类非常困难 |
| 无用负样本（排序可用） | 曝光但没点击的物品 | 该物品作为召回负样本是**错误**的，但可以作为**排序**的负样本 |

**Batch 内负样本的纠偏**：物品 i 被抽样到的概率 p_i ∝ 点击次数。训练时把预估兴趣分数 `cos(a, b_i)` 调整为 `cos(a, b_i) − log p_i`，以降低热门物品成为负样本的概率（采样偏置修正，参考文献：Xinyang Yi et al., RecSys 2019）。

训练时通常混合多种负样本：**50% 全体物品（简单）+ 50% 没通过排序的物品（困难）**。

> 关键记忆：曝光但未点击的物品**不能做召回的负样本**——用户可能感兴趣，只是碰巧没点。它适合做排序模型的负样本。

### 线上召回和更新

**离线存储物品向量**：

1. 完成训练后，用物品塔计算每个物品的特征向量 b
2. 把几亿个物品向量 b 存入向量数据库（Milvus、Faiss、HnswLib）
3. 向量数据库建立索引，加速最近邻查找

**线上召回**：

1. 给定用户 ID 和画像（多维特征属性），线上用用户塔现算用户向量 a
2. 把 a 作为 query 调用向量数据库做最近邻查找，返回余弦相似度最大的 k 个物品

为什么物品向量离线算、用户向量线上算？

1. 每次召回只用 1 个用户向量，却要对比几亿个物品向量，线上算物品向量代价太大
2. 用户兴趣动态变化，物品特征相对稳定。虽然可以离线存用户向量，但不利于实时推荐效果

**全量更新 vs 增量更新**：

| 更新类型 | 全量更新 | 增量更新 |
| --- | --- | --- |
| 基本思想 | 今天凌晨，用昨天的全天数据，在昨天发布的全量模型参数基础上训练（**不是随机初始化**，也不是昨天的增量模型） | 用户兴趣随时变化，做 online learning 更新模型参数 |
| 基本流程 | ① 用昨天数据训练 1 epoch，每天数据只用一遍；② 发布新的用户塔神经网络和物品向量 | ① 实时收集线上数据、流式处理生成 TFRecord；② 只增量更新 ID Embedding 参数；③ 发布最新用户 ID Embedding |
| 注意事项 | 对数据流、系统的要求比较低 | 只更新用户 ID Embedding，不更新神经网络其他部分（锁住全连接层） |

能否只做增量更新？

不能：

1. 不同时间段用户行为不同，以天为总体，小时级数据有偏、分钟级偏差更大
2. 全量更新把一天数据 random shuffle 后训练 1 epoch；增量更新按时间从早到晚的顺序训练。随机打乱优于按顺序排列，所以全量训练往往优于增量训练

实际系统：**全量 + 增量结合**，每隔几十分钟发布最新用户 ID Embedding。

## 7. 自监督学习

### 动机

基于双塔的推荐系统存在严重的**头部效应**：少部分物品占据大部分点击，大部分物品点击次数不多，所以系统对高点击物品的表征学得好，对**长尾（低曝光）物品的表征学习困难**。

引入自监督学习，对物品做 data augmentation，可以更好地学习长尾物品的向量表征。

### 基本思想

召回中的自监督学习更像一个**辅助任务**：帮助系统从已有数据中挖掘更多自监督信号（调整物品塔参数），同时不同的特征变换能产生更多向量表征，起到数据增强的作用。

训练目标：

1. 希望物品 i 的两个向量表征 b′_i 和 b″_i 有较高相似度，鼓励 cos(b′_i, b″_i) 尽量大
2. 希望不同物品 i、j 的任意向量表征（如 b′_i 和 b″_j）相似度较低，鼓励 cos(b′_i, b″_j) 尽量小

物品塔是**同一个塔、共享参数**，对同一物品做两类特征变换得到两组向量。

### 特征变换方法

| 特征变换 | 基本思想 | 示例 |
| --- | --- | --- |
| Random Mask | 随机挑选一些离散特征遮住 | 类目特征 u={数码, 摄影} → u={default} |
| Dropout（仅对多值离散特征生效） | 随机丢弃特征中 50% 的值 | 类目 [1,2] → [1,0] |
| 互补特征（complementary） | 把特征随机分成两组，两组表征同一物品、特征互不重复，鼓励两个向量相似 | {ID、类目、关键词、城市} → {ID, default, 关键词, default} 与 {default, 类目, default, 城市} |
| Mask 一组关联的特征 | 用互信息衡量特征关联度，选一个种子特征，连同最相关的 k/2 个特征一起 Mask；效果最好，但复杂、难维护 | 共 k 种特征，离线算 k×k 的 MI 矩阵，随机选 seed，Mask seed 及最相关 k/2 种，保留其余 k/2 种 |

互信息公式（特征 1 取值集合 U、特征 2 取值集合 V，p(u)、p(v) 为单特征取值的概率，p(u,v) 为同时发生的概率）：

```
MI(U,V) = Σ_{u∈U} Σ_{v∈V} p(u,v) · log( p(u,v) / (p(u)·p(v)) )
```

### 模型训练

自监督学习的训练流程：

1. 从全体物品中**均匀抽样** m 个物品作为一个 batch
2. 对物品做两类特征变换，物品塔输出两组向量 b′₁…b′_m 和 b″₁…b″_m
3. 第 i 个物品的损失：

```
L_SSL(i) = −log( exp(cos(b′_i, b″_i)) / Σ_j exp(cos(b′_i, b″_j)) )
```

4. 梯度下降减小自监督损失

加入双塔模型联合训练：

1. 对点击数据随机采样 n 对「用户—物品」二元组做一个 batch
2. 从全体物品均匀抽样 m 个物品做一个 batch
3. 联合损失（双塔损失 + α × 自监督损失），α 是超参数，控制自监督的影响程度

```
总损失 = Σ L_dual(i) + α · Σ L_SSL(j)
```

参考文献：Yao et al., Self-supervised Learning for Large-scale Item Recommendations, CIKM 2021。

## 8. Deep Retrieval

经典双塔把用户、物品表示为向量做最近邻查找；Deep Retrieval 把**物品表征为路径（path）**，线上查找用户最匹配的路径，类似阿里的 TDM。

- 路径结构：深度 3、宽度 K，一条路径如 [2,4,1]；一个物品可对应多条路径
- 两个索引：`item → List<path>`、`path → List<item>`
- 预估模型：神经网络预估用户对路径的兴趣

```
p(path=[a,b,c] | x) = p(a|x) × p(b|a;x) × p(c|a,b;x)
```

线上召回（用户 → 路径 → 物品）：

1. 给定用户特征，用 **beam search** 找分数最高的 s 条路径（避免枚举全部 K³ 条路径；beam size=1 即贪心，未必最优）
2. 利用 `path → List<item>` 索引，召回每条路径上的 n 个物品（共 s×n 个）
3. 对物品做初步排序，返回分数最高的若干物品

训练：同时学习两部分——

1. **神经网络参数（用户—路径）**：正样本是点击的 (user, item)；物品被表征为 J 条路径，用户点击过物品说明用户对这 J 条路径感兴趣，让 `Σ p(path_j | x)` 变大，损失 `−log Σ p(path_j | x)`
2. **物品表征（物品—路径）**：`score(item, path) = Σ_user p(path|user) × click(user, item)`；为每个物品选 J 条最相关的路径，加正则项避免一条路径上物品过多，用贪心算法逐条更新

参考文献：Gao et al., CIKM 2021；Zhu et al., KDD 2018。

## 9. 其他召回通道

| 召回通道 | 原理 | 索引 | 召回流程 |
| --- | --- | --- | --- |
| GeoHash 召回 | 用户可能对附近发生的事感兴趣，按定位取该地点最新优质笔记 | GeoHash → 优质笔记列表（按时间倒排） | 无个性化召回 |
| 同城召回 | 用户可能对同城的事感兴趣 | 城市 → 优质笔记列表（按时间倒排） | 无个性化召回 |
| 关注作者召回 | 用户对关注的作者发布的笔记感兴趣 | 用户 → 关注的作者；作者 → 发布的笔记 | 用户 → 关注的作者 → 最新笔记 |
| 有交互的作者召回 | 用户点赞/收藏/转发某笔记，可能喜欢该作者其他笔记 | 用户 → 有交互的作者 | 用户 → 有交互的作者 → 最新笔记 |
| 相似作者召回 | 用户喜欢某作者，可能喜欢相似作者（类似 ItemCF） | 用户 → 感兴趣的作者；作者 → 相似作者 | 用户 → 感兴趣的作者 → 相似作者 → 最新笔记 |

> Tip：视频里有交互作者召回和相似作者召回只写了一条索引，个人理解是前面的召回通道已建立过「作者 → 发布的笔记」等索引，所以只列出新增索引。可能存在其他实现方式，请以视频为准。

**缓存召回**：精排输出几百篇进重排，但重排只选出几十篇曝光，大部分精排结果被浪费。缓存召回复用「前 n 次推荐精排但没有曝光」的结果（如精排前 50），作为一条召回通道。缓存大小固定，需要退场机制：

1. 笔记一旦成功曝光，就从缓存退场
2. 超过缓存大小，移除最先进入缓存的笔记
3. 笔记最多被召回若干次，达到次数就退场
4. 每篇笔记最多保存若干天，达到天数就退场
5. 扩展：可以让低曝光笔记缓存更长时间，基于曝光次数设置退场规则

## 10. 曝光过滤 & Bloom Filter

### 曝光过滤

小红书、抖音等推荐系统为避免重复推荐，用户看过某个物品后就不再曝光给该用户。曝光过滤一般在召回层实现（召回之后、排序之前）：

1. 对每个用户记录已经曝光给他的物品（小红书只召回 1 个月以内的笔记，所以只需记录最近 1 个月的曝光历史）
2. 对每个召回的物品，判断是否已曝光，排除曾曝光过的物品

一位用户看过 n 个物品、本次召回 r 个物品，暴力对比需要 O(nr) 时间，代价过大。

### Bloom Filter

用 Bloom Filter 判断一个物品 ID 是否在已曝光的物品集合中：

- 判断为 **no**：该物品一定不在集合中（无假阴性）
- 判断为 **yes**：该物品很可能在集合中，可能**误伤**（把未曝光误判为已曝光并过滤掉）

实现原理：

1. 把物品集合表征为一个 m 维二进制向量；每个用户有一个曝光集合，需要 m bit 存储
2. 有 k 个哈希函数，每个把物品 ID 映射成 0~m−1 之间的整数
3. 添加已曝光物品：把 k 个哈希位置的 bit 置 1（原本是 1 则不变）
4. 查询召回物品：若 k 个位置全为 1 则判为已曝光，否则未曝光

误伤率：设集合大小 n、向量维度 m、哈希函数个数 k：

```
δ ≈ (1 − exp(−kn/m))^k
```

规律：

1. n 越大，向量中 1 越多，误伤率越大（未曝光物品的 k 个位置恰好都是 1 的概率大）
2. m 越大，向量越长，越不容易发生哈希碰撞
3. k 太大太小都不好，有最优取值
4. 设定可容忍误伤率 δ 后，最优参数：`k ≈ 1.44·ln(1/δ)`，`m ≈ 2n·ln(1/δ)`

曝光过滤链路：

```
召回（多路）→ 曝光过滤服务（Bloom Filter 查询）→ 排序
                    ↑
        实时流处理（Kafka + Flink）写入曝光事件
```

**缺点**：Bloom Filter 只支持添加、不支持删除。添加物品只需把 k 个位置置 1；删除时如果把 k 个位置置 0，会误删其他物品的信息。因此每天要清理超龄（>1 个月）物品时无法直接删除，只能重新构建（降低 n 也可以降低误伤率）。

参考文献：Bloom, Space/time trade-offs in hash coding with allowable errors, CACM 1970。

## 11. 本章小结

召回的目的在于快速从几亿个物品中初步筛选出几千个物品。基于统计学、规则和神经网络的召回方法都是行之有效的手段，协同过滤是其中基础和经典的思想。

本章先介绍了 ItemCF 和 UserCF 两种协同过滤：它们用物品/用户 ID 计算相似度，结合交互信息算兴趣分数排序作为召回结果。但工业场景物品以亿计，协同过滤使用的稀疏向量过于庞大稀疏，计算复杂度高。

因此引入用 embedding 处理离散特征的**矩阵补全模型**。但矩阵补全只用 ID 做 embedding、负样本选取错误、用内积做回归训练，实际效果不佳。

在此基础上改进得到**双塔模型**：使用多维特征属性，后期融合、先各自生成表征再算余弦相似度；负样本混合选取简单负样本和困难负样本；训练任务转化为分类，按 pointwise/pairwise/listwise 对应交叉熵或合页损失。

但双塔存在严重的头部效应，对长尾数据处理不好。于是引入**自监督学习**，用多种特征变换（Mask、Dropout、互补等）做数据增强，更好地学习用户和物品表征。

除了协同过滤，本章还介绍了地理位置（GeoHash/同城）、作者（关注/交互/相似）等简单召回通道，以及通过退场机制复用精排未曝光结果的**缓存召回**。

实际部署时，模型需要推全上线：线上用**最近邻查找**输出召回结果，原始暴力查找代价太大，要用近似最近邻等方法加速；同时离线存储物品表征、建立索引降低线上计算量；模型上线后用全量 + 增量更新迭代。

最后，为避免重复推荐，需要在召回层做**曝光过滤**。Bloom Filter 是常用方法，但它只支持添加、不支持删除，且存在一定误伤概率。

## 复习速记

- **ItemCF**：用户喜欢 i₁，i₁ 与 i₂ 相似 → 推荐 i₂；相似度 = 受众重合的余弦；索引「用户→last-n 物品」「物品→top-k 相似」；线上打分返回 Top 100
- **Swing**：解决小圈子问题，重合用户重合度越高权重越低：`ΣΣ 1/(α + overlap(u_a,u_b))`
- **UserCF**：相似用户喜欢的物品推荐给我；相似度 = 共同物品的余弦，热门物品降权 `1/log(1+n_l)`
- **ItemCF vs UserCF**：一个先查用户→物品再查物品→物品；一个先查用户→用户再查用户→物品，索引顺序不同
- **离散特征**：类别多时用 embedding 不用 one-hot；embedding 参数 = 维度 × 类别数
- **矩阵补全三大缺点**：只用 ID embedding、负样本选错、内积 + 平方损失训练不好
- **双塔模型**：后期融合（先表征后算相似度）适合召回；前期融合（concat 后过网络）适合排序；物品向量离线存、用户向量线上算，ANN 加速
- **三种训练**：pointwise（交叉熵）、pairwise（hinge/logistic triplet loss）、listwise（sampled softmax）
- **负样本**：正样本 = 曝光且点击；简单负样本 = 全体物品（抽样 ∝ 点击^0.75）、batch 内负样本（cos − log p 纠偏）；困难负样本 = 被排序淘汰的；**曝光未点击不能做召回负样本，排序可以用**
- **模型更新**：全量（每天凌晨、前一天数据、1 epoch、基于昨天全量模型）+ 增量（只更新 ID embedding）；不能只做增量，因为按时序数据有偏
- **自监督学习**：解决长尾物品表征学不好；特征变换有 random mask、dropout、互补特征、mask 关联特征（MI）
- **Deep Retrieval**：物品表征为路径，beam search 找路径，路径索引召回物品；训练同时学神经网络参数和物品表征
- **其他通道**：GeoHash/同城（无个性化）、关注/交互/相似作者、缓存召回（复用精排未曝光结果 + 退场机制）
- **Bloom Filter**：m 位向量 + k 个哈希函数，无假阴性有误伤；只支持添加不支持删除；误伤率 δ ≈ (1−exp(−kn/m))^k
