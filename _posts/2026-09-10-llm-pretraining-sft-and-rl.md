## 1. 四种训练方式的主线

| 方式 | 主要数据／信号 | 学习目标 |
|---|---|---|
| 预训练 | 大量文本 | 根据前文预测后续 token |
| SFT | 输入与示范回答 | 学习期望的任务行为 |
| RL | 模型生成结果获得的奖励 | 提高策略的期望奖励 |
| DPO | 同一问题下的 chosen/rejected 偏好对 | 优化回答之间的相对偏好 |

这些是训练方式，不要求每个模型严格按这个顺序全部经历一遍。训练会更新可训练参数；普通生成通常固定参数。

## 2. 预训练：标签来自文本本身

例如文本切分为：

```text
北京 / 是 / 中国 / 的 / 首都 / 。

输入：北京  是    中国  的    首都
标签：是    中国  的    首都  。
```

模型输出 logits，与向后错一位的标签计算交叉熵，再反向传播、更新参数。标签直接来自文本，通常称为自监督学习。

第三步的小 GPT 实验使用了同类 next-token prediction 目标，但只在一条示例序列上更新一次，不能视为完成了实际的大规模预训练。

模型从大量文本中学习语言结构、知识关联和一定的任务能力。续写目标本身并没有明确要求按用户指令回答，基础模型可能延续不同文本模式。

## 3. SFT：用示范回答继续训练

SFT 是 Supervised Fine-Tuning，即监督微调。在已有模型上，用任务示范继续训练。

```text
用户：请把“苹果”翻译成英文。
助手：apple
```

聊天模板将它组织成一条序列，简化表示为：

```text
<用户> 请把“苹果”翻译成英文。 <助手> apple <结束>
```

SFT 仍可使用 next-token 交叉熵。一种常见配置仅对回答 token 和适当的结束标记计算损失：

$$
L_{\mathrm{SFT}}=-\sum_{t\in\mathcal{A}}
\log P_\theta(y_t\mid x,y_{<t})
$$

其中 x 是提示，y 是示范回答，A 表示参与损失的回答位置。实现通常还会按有效 token 数归一化。

正确回答已在训练数据中提供，因此训练可并行计算各位置预测。不同配置也可能对整段序列计算损失。

### Causal mask 与 Loss mask

| Mask | 控制什么 |
|---|---|
| Causal mask | 每个位置能读取哪些位置 |
| Loss mask | 哪些目标 token 的预测计入损失 |

问题部分不计直接预测损失，也仍然作为上下文进入模型。回答位置可以通过 Attention 读取问题；回答的损失也能沿计算路径反向传播到处理问题的参数。

### 为什么这里仍是 Self-attention

学习时提出的问题：“回答读取问题，是否类似 cross-attention？”

判别依据是 Q/K/V 的来源：

- Decoder-only SFT 把问题与回答拼成同一序列，Q/K/V 来自同一序列在该层的表示，因此是 causal self-attention。
- 经典 encoder–decoder cross-attention 的 Q 来自 decoder，K/V 来自 encoder 输出。

文本角色不同，不会自动使注意力变成 cross-attention。

## 4. RL：生成、评分、更新

语言模型强化学习的基本流程：

```text
问题 → 模型采样回答 → 获得奖励 → 计算优化目标 → 更新模型
```

以数学题为例：

```text
问题：17 × 19 等于多少？
回答 A：323 → 奖励 1
回答 B：313 → 奖励 0
```

| RL 术语 | LLM 中的对应 |
|---|---|
| Policy（策略） | 模型的下一个 token 概率分布 |
| State（状态） | 问题与已生成前缀 |
| Action（动作） | 选择一个 token |
| Reward（奖励） | 对结果或过程的评分 |

生成回答是收集训练样本的环节，之后还会进行优化；普通聊天推理没有这一步参数更新。

### RLVR：可验证奖励

可用答案核对、代码测试等获得奖励。验证器有覆盖范围，通过有限测试不保证所有输入都正确。

### 经典 RLHF：从人类偏好学习奖励

```text
人类比较同一问题的回答 A/B
            ↓
用偏好对训练 Reward Model
            ↓
奖励模型为语言模型新生成的回答打分
            ↓
用奖励进行 RL 更新
```

不需要每轮都由人现场评分。奖励模型是对偏好的近似，奖励高不保证真实质量一定高。

## 5. 奖励如何影响更新方向

一种入门直觉是把奖励与基准比较，得到 advantage（优势）。例如三份回答奖励为 `[1, 0, 0]`，以组内平均 1/3 为教学基准：

```text
优势：[2/3, -1/3, -1/3]
```

简化策略梯度损失可以写成：

$$
L=-A\log P_\theta(y\mid x)
$$

- A>0：梯度方向倾向提高该回答的概率。
- A<0：梯度方向倾向降低该回答的概率。
- A 在这个示意损失中作为固定权重处理。

这是更新方向的示意，省略了实际算法的估计细节、概率比值、裁剪、参考策略约束等。共享参数与批量优化下，不保证每个样本更新后的概率都严格按此方向变化。

奖励可以来自不可微的判题程序：训练通过模型自身的 log 概率计算梯度，不需要对判题程序或离散采样操作直接求导。

## 6. DPO：直接用偏好对训练

典型数据：

```text
prompt：解释什么是 Attention。
chosen：清楚、准确的回答。
rejected：存在错误的回答。
```

标准离线 DPO 直接用这些偏好对更新语言模型，通常不需要另训显式奖励模型，也不要求训练时持续在线生成回答。

它相对于固定参考模型，优化 chosen 对 rejected 的相对偏好。不能简单理解为每次更新都会提高 chosen 的绝对概率。

DPO 属于偏好优化，不能将所有偏好优化都等同于在线 RL。

## 7. 训练目标与参数更新范围是两个选择

```text
SFT + 全量微调：更新整个模型
SFT + LoRA：通常冻结原有权重，训练新增的低秩参数
```

LoRA 描述一种参数高效适配方式；看到 LoRA，还要查看数据与 loss，才能知道模型在学习什么。具体可训练参数以配置为准。

## 8. 对照同一任务

| 方式 | “把苹果翻译成英文”的训练材料 |
|---|---|
| 预训练 | 文本“苹果的英文是 apple。” |
| SFT | 问题与示范回答“apple” |
| RLVR | 生成回答，程序检查是否正确并给奖励 |
| 经典 RLHF | 用偏好训练的奖励模型给生成回答评分 |
| DPO | chosen 为 apple、rejected 为 banana 的偏好对 |

## 9. 与推荐任务衔接

学习时的场景判断：给定用户行为，学习示范推荐输出，判断为 SFT；先生成推荐列表，再按反馈奖励优化，判断为 RL。已正确区分。

进一步区分：

- 直接用历史下一个物品作标签，通常叫监督式 next-item prediction。
- 将任务组织为指令—回答，在已有模型上微调，称为 SFT 更贴切。
- 把点击作为标签训练点击率预测器，也可以是监督学习。
- 是否属于 RL，要看如何收集数据和优化策略，不能仅凭“使用用户反馈”判断。
