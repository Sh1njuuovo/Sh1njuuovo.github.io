参考课程：[王树森《工业界的推荐系统》](https://github.com/wangshusen/RecommenderSystem)第七章
课件：`Slides/07_ColdStart_01.pdf` ~ `07_ColdStart_06.pdf`

物品冷启动指的是**如何对新发布的物品做分发**，例如：

1. 小红书上用户新发布的笔记
2. B 站上用户新上传的视频
3. 今日头条上作者新发布的文章

这些内容都由用户上传，所以主要研究 **UGC（User-Generated Content）** 的物品冷启动。UGC 比 PGC（主要内容由平台采购）的冷启动更难：UGC 的新物品数量巨大、内容质量良莠不齐，分发非常困难。

为什么新内容要特殊对待？

1. 新笔记缺少与用户的交互，导致推荐的难度大、效果差
2. 扶持新发布、低曝光的笔记，可以增强作者发布意愿

---

## 1. 优化目标 & 评价指标

### 优化冷启的目标

工业界对冷启动目标的共识：

1. **精准推荐**：克服冷启困难，把新笔记推荐给合适的用户，不引起反感
2. **激励发布**：流量向低曝光新笔记倾斜，激励作者发布
3. **挖掘高潜**：通过初期小流量试探，找到高质量笔记并给予流量倾斜

### 评价指标

冷启的评价远比普通笔记复杂（普通笔记只需考察用户侧指标），需要三类指标：

| 指标类型 | 指标 | 基本思想 | 意义 |
| --- | --- | --- | --- |
| 作者侧指标 | 发布渗透率、人均发布量 | 发布渗透率 = 当日发布人数*/日活人数；人均发布量 = 当日发布笔记数/日活人数 | 反映作者发布积极性：冷启要促进发布、增大内容池，新笔记曝光越多、首次曝光和交互越早，作者积极性越高 |
| 用户侧指标 | 新笔记的消费指标 | 考察新笔记点击率、交互率，并分别考察高曝光（>1000 次）、低曝光（<1000 次） | 只考察整体会受基尼系数误导：少数头部新笔记占据大部分曝光，要区别对待高低曝光笔记 |
| 用户侧指标 | 大盘消费指标 | 大盘消费时长、日活、月活 | 低曝光笔记缺少交互、推荐不准，一味扶持会损害体验、拉低大盘；新策略实验希望大盘基本持平 |
| 内容侧指标 | 高热笔记占比 | 前 30 天获得 1000+ 次点击的笔记占比 | 占比越高，说明冷启阶段挖掘优质笔记的能力越强 |

*：发布一篇或以上就算一个发布人数。

### 冷启动的优化点

1. **优化全链路**：包括优化召回和排序
2. **流量调控**：流量怎么在新物品、老物品之间分配

## 2. 冷启动召回：简单召回通道

### 召回依据与困难

新笔记自带图片、文字、地点和算法/人工标注的标签，但缺乏用户点击、点赞等信息，没有笔记 ID embedding，导致冷启召回困难：

1. 缺少用户交互，笔记 ID embedding 没学好，双塔模型效果不好（召回和排序中存在同样问题）
2. 缺少用户交互，ItemCF 不适用：新笔记交互少，与其他笔记的用户重合度未知，无法计算相似度

各召回通道适用性：

| 召回通道 | 物品冷启动适用性 |
| --- | --- |
| ItemCF 召回 | 不适用 |
| 双塔模型 | 改造后适用 |
| 类目、关键词召回 | 适用 |
| 聚类召回 | 适用 |
| Look-Alike 召回 | 适用 |

### 改进的双塔模型

**方案 1：新笔记使用 default embedding**

- 物品塔做 ID embedding 时，让所有新笔记共享一个 ID（而非自己的真实 ID），共享 ID 对应的 embedding 向量就是 default embedding，该向量通过训练学习得到
- 到下次模型训练时，新笔记才有自己的 ID embedding

**方案 2：利用相似笔记的 embedding**

- 新笔记发布后，查找 top-k 内容最相似的高曝笔记（高曝笔记的向量学得好）
- 把 k 个高曝笔记的 embedding 取平均，作为新笔记的 embedding

实践中还设置**多个向量召回池**增加新笔记曝光机会：1 小时新笔记、6 小时新笔记、24 小时新笔记、30 天笔记。召回池共享同一个双塔模型，多个池**不增加训练代价**。

### 类目、关键词召回

用户画像记录了用户感兴趣的类目（美食、科技数码等）和关键词（纽约、职场、程序员等）：

1. 系统维护类目索引：`类目 → 笔记列表（按时间倒排）`
2. 召回：用户画像 → 类目 → 笔记列表
3. 取回列表上前 k 篇笔记（即最新的 k 篇）

基于关键词的召回与类目召回本质相同，把「类目」替换成「关键词」即可。

缺点：

1. 只对**刚刚发布**的新笔记有效：只取某类目/关键词下最新的 k 篇，发布几小时后就没有机会被召回
2. 弱个性化、不够精准

## 3. 聚类召回

### 基本思想与索引

聚类召回基于笔记的图文内容做推荐：**如果用户喜欢一篇笔记，那么他会喜欢内容相似的笔记**。

1. 线下训练一个神经网络，基于笔记的类目和图文内容把笔记映射成向量
2. 对笔记向量做聚类（k-means，余弦相似度），划分为 1000 个 cluster，记录每个 cluster 的中心方向

新笔记发布后建立聚类索引：

1. 用神经网络把新笔记映射成特征向量
2. 从 1000 个 cluster 向量中找到最相似的，作为新笔记所属 cluster
3. 索引：`cluster → 笔记 ID 列表（按时间倒排）`

### 线上召回

1. 给定用户 ID，找到 last-n 交互的笔记列表作为**种子笔记**
2. 把每篇种子笔记映射到向量，寻找最相似的 cluster（知道用户对哪些 cluster 感兴趣）
3. 从每个 cluster 的笔记列表取回最新的 m 篇，最多取回 mn 篇新笔记

聚类召回与类目/关键词召回相似，**只对刚刚发布的新笔记有效**。

### 内容相似度模型

模型把笔记图文分别通过 CNN（图片）和 BERT（文字）生成向量，拼接后输入全连接层，输出笔记内容表征向量；两篇笔记的相似度用余弦相似度。**CNN 和 BERT 是预训练好的模型，全连接层的参数通过训练学习。**

训练方法与双塔模型的 Pairwise 方式类似：设正样本、种子、负样本笔记的向量为 b⁺、a、b⁻，鼓励 cos(a,b⁺) 大于 cos(a,b⁻)：

```
Triplet hinge loss:    L = max(0, cos(a,b⁻) + m − cos(a,b⁺))
Triplet logistic loss: L = log(1 + exp(cos(a,b⁻) − cos(a,b⁺)))
```

正样本选取：

1. 人工标注二元组的相似度，选高相似度作为正样本
2. 算法自动选：只用高曝光笔记（有充足交互信息）、要求两篇笔记有相同的二级类目、再用 ItemCF 的物品相似度选正样本

负样本选取：从全体笔记随机选满足条件的——字数较多（保证神经网络提取的文本信息有效）、笔记质量高（避免图文无关）。

## 4. Look-Alike 召回

Look-Alike（人群扩散算法）是广告中常用的方法，也可用于推荐系统中召回低曝光笔记。

### 互联网广告中的 Look-Alike

以 Tesla Model 3 为例：典型用户有明确特征（25~35 岁、本科以上、关注科技数码、喜欢苹果产品），满足条件的用户作为**种子用户**。但种子用户数量很少，潜在用户受众很多却缺少部分信息无法直接寻找，所以通过种子用户做**人群扩散**，找到相似的 Look-Alike 用户。

Look-Alike 是一个**框架**，具体做人群扩散的方法很多，核心任务是如何计算两个用户的相似度：

- UserCF：两个用户有共同的兴趣点
- Embedding：两个用户向量的余弦相似度较大

### Look-Alike 人群扩散召回

1. 点击、点赞、收藏、转发说明用户对笔记可能感兴趣
2. 把有交互的用户作为新笔记的**种子用户**
3. 用 Look-Alike 在相似用户中扩散

实现细节：

- 新笔记发布后，取有交互用户的特征向量（如双塔模型），把它们的**平均**作为新笔记的特征向量
- **近线更新**：每当有用户交互该笔记，就更新笔记的特征向量
- 线上召回：新笔记特征向量存入向量数据库；用户刷小红书时用双塔模型计算用户向量作为 query，在向量库做最近邻查找，取回几十篇笔记

### Tip：物品从发布到热门的三阶段透出渠道

1. **类目召回、聚类召回**：基于内容的召回通道，适用于**刚刚发布**的物品
2. **Look-Alike 召回**：适用于**有点击但点击次数不高**的物品
3. **双塔、ItemCF、Swing 等**：基于用户行为的召回通道，适用于**点击次数较高**的物品

## 5. 流量调控

流量调控是冷启动的第二种优化点，也是物品冷启动**最重要的一环**：它直接控制流量怎么在新笔记、老笔记之间分配，直接影响作者发布指标。

工业界一般把流量向新笔记倾斜，目的有二：

1. **促进发布、增大内容池**：新笔记曝光越多，作者创作积极性越高（反映在发布渗透率、人均发布量）
2. **挖掘优质笔记**：做探索让每篇新笔记获得足够曝光（能力反映在高热笔记占比）

工业界做法示例：假设系统只分发年龄 <30 天的笔记，自然分发下新笔记（<24 小时）曝光占比为 1/30；扶持新笔记就是让它远大于 1/30。

### 流量调控技术的发展

```
1. 在推荐结果中强插新笔记
2. 对新笔记的排序分数做提权（boost）
3. 通过提权，对新笔记做保量
4. 差异化保量
```

### 新笔记提权（boost）

粗排会截断、重排会抽样，两道工序过滤大量笔记。想让新笔记占到更多曝光，就要在粗排、重排环节给新笔记提权。

优点：容易实现、投入产出比好
缺点：

1. 曝光量对提权系数很敏感
2. 很难精确控制曝光量，容易过度曝光和不充分曝光

### 新笔记保量

保量：不论笔记质量高低，都保证新笔记在 24 小时内获得 100 次曝光。做法是在原有提权系数的基础上乘以额外提权系数：发布时间越接近 24 小时、曝光次数与 100 差得越多，额外系数越大。

更先进的**动态提权保量**，用四个值计算提权系数：

```
目标时间（如 24 小时）、目标曝光（如 100 次）
发布时间（如已发布 12 小时）、已有曝光（如 20 次）
提权系数 = f(发布时间/目标时间, 已有曝光/目标曝光)
例：f(12/24, 20/100) = f(0.5, 0.2)
```

前一个比例越大（时间进度落后）、后一个比例越小（曝光进度落后），提权系数越大。

保量的难点：

1. **保量成功率远低于 100%**：很多笔记 24 小时内达不到 100 次曝光（召回、排序不足；提权系数调得不好）
2. **线上环境变化导致保量失败**：新增召回通道、升级排序模型、改变重排打散规则后，需要重新调整提权系数

为了提升成功率，大幅增加额外系数可行吗？给新笔记 boost 越多影响是双面的：

- 好处：短期分数提升越多、曝光越多
- 坏处：把笔记推荐给不太合适的受众，点击率、点赞率偏低；长期会被推荐系统打压，难以成长为热门笔记

所以保量的系数调整十分关键。

### 差异化保量

不同笔记有不同的保量目标：普通笔记保 100 次曝光，内容优质的笔记保 100~500 次，具体由算法判定：

1. 基础保量：24 小时 100 次曝光
2. 内容质量：用模型（多模态神经网络）评价内容质量，给予额外保量目标（上限 +200 次）
3. 作者质量：根据作者历史笔记质量，给予额外保量目标（上限 +200 次）
4. 一篇笔记最少 100 次、最多 500 次

达到保量目标后停止扶持、自然分发，与老笔记公平竞争。

## 6. 冷启动的 A/B 测试

冷启动的 A/B 测试比普通推荐系统麻烦得多：普通 AB 只考察用户侧消费指标，冷启动还要考察**作者侧发布指标**，而且所有已知实验方案都有缺陷。

### 用户侧实验

与标准推荐系统一致：全部用户划分对照组和实验组，用新旧策略在全部笔记上测试，得到新笔记点击率、用户消费时长等指标的 diff。

但存在瑕疵。设：

- 限定：保量 100 次曝光
- 假设：新笔记曝光越多，用户使用 APP 时长越低（新笔记推荐不够准，体验差）
- 新策略：新笔记排序权重增大两倍

结果（只看用户消费指标）：AB 的 diff 是负数（实验组不如对照组）；但**如果推全，diff 会缩小**（如 −2% → −1%）。原因：测试时实验组看到更多新笔记导致消费变差、对照组看到更少新笔记导致消费变好，此消彼长拉大了 diff；推全后不再此消彼长，diff 不会下降那么多。

### 作者侧实验

**方案一：只把新笔记分桶**

不对用户和老笔记分组，只区分新笔记和老笔记：新笔记按新旧策略分成对照组和实验组，老笔记自然分发、不受策略影响。新笔记的两组都有机会触达所有用户，对比得到指标 diff。

缺点 1——**新笔记之间抢流量**：

- 设定：新老笔记走各自队列不竞争，重排分给新笔记 1/3、老笔记 2/3 流量
- 新策略：新笔记权重增大两倍
- 结果：AB diff 为正（实验组优于对照组）；**推全后 diff 消失**（如 +2% → 0）
- 原因：新笔记流量固定，实验组权重提高、曝光增加，对照组曝光就被挤掉；推全后没有对照组可抢，diff 消失

缺点 2——**新笔记和老笔记抢流量**：

- 设定：新老笔记自由竞争
- AB 时是「50% 带策略的新笔记 vs 100% 老笔记」；推全后变成「100% 带策略的新笔记 vs 100% 老笔记」
- 推全前后设定变了，所以 AB 结果与推全结果有差异

**方案二：新笔记 + 用户都分桶**

与方案一的区别：用户侧也分对照组和实验组，对照组只能看到对照组的新笔记、实验组只能看到实验组的新笔记。

- 优点：新笔记的两个桶不抢流量，作者侧实验更可信
- 相同问题：新笔记和老笔记仍抢流量，AB 与推全结果有差异
- 缺点：新笔记内容池减小一半，对用户体验造成负面影响

**方案三：新笔记 + 用户 + 老笔记全分桶**

在方案二基础上把老笔记也分桶，对照组只能看到对照组的新老笔记和用户——相当于**把小红书切成两个 app 独立测试**，指标变化真实有效、结果最准确。

但实际上不可行：内容池缩小一半、严重影响用户体验，消费指标一定大跌。为了 AB 测试损害公司业务，代价过于庞大。

### 总结

冷启 AB 各种方案都有缺点（哪怕小红书的方案也不完美）。设计时要问自己：

1. 实验组、对照组的新笔记会不会抢流量？
2. 新笔记、老笔记怎么抢流量？
3. 同时隔离笔记和用户，会不会让内容池变小？
4. 如果对新笔记做保量，会发生什么？

## 7. 本章小结

本篇记录 UGC 物品冷启动，也就是用户新发布笔记的分发曝光。优化目的：精准推荐、激励发布、挖掘高潜；对应同时考察作者侧、用户侧、内容侧三类指标，分别反映发布意愿、推荐精准度和优质笔记挖掘能力。优化手段主要有两种：**优化全链路**和**流量调控**。

召回侧有三类通道，对应物品从发布到热门的三阶段：

1. **类目召回、聚类召回**（基于内容，适用刚发布）：类目召回按用户画像的兴趣类目找该类目最新笔记，个性化弱、只对刚发布有效；聚类召回把图文内容映射成向量并聚类，线上用种子笔记找相似 cluster、取最新笔记
2. **Look-Alike 召回**（适用有点击但点击不高的物品）：思想与 UserCF 相似，找与种子人群相似的人群扩散推荐；实践中用有交互用户向量的平均作为新笔记特征向量并近线更新
3. **双塔、ItemCF、Swing**（基于用户行为，适用点击高的物品）：标准双塔因缺少交互和 ID embedding 无法直接使用，改进方案是在下次训练前用 default embedding 或相似笔记 embedding 作为新笔记向量

流量调控解决新老笔记之间的流量分配：单独召回通道 + 排序阶段提权。提权易实现但系数和曝光量难把控，于是做保量（24 小时 100 次曝光）；简单保量失败率高、直接大幅提权又不可取，最终演进到按内容质量、作者质量做**差异化保量**。

冷启 AB 要同时看作者侧和用户侧，远比标准推荐复杂。用户侧实验有「推全后 diff 缩小」的瑕疵；作者侧三种方案各自有缺陷——方案一新笔记互相抢流量（推全 diff 消失）、新老笔记抢流量（AB 与推全有差异）；方案二解决新笔记互抢但内容池减半；方案三等于切两个 app，结果准但代价不可接受。

## 复习速记

- 冷启目标：精准推荐（不引起反感）、激励发布（发布渗透率/人均发布量）、挖掘高潜（高热笔记占比）
- 指标三侧：作者侧（发布渗透率、人均发布量）、用户侧（新笔记 CTR/交互率分高低曝光看 + 大盘消费）、内容侧（前 30 天 1000+ 点击的高热笔记占比）；普通推荐只需看用户侧
- 冷启召回难点：无交互 → ItemCF 不适用（重合度未知）、双塔 ID embedding 没学好
- 双塔改造：default embedding（共享 ID、训练学到）、相似高曝笔记 embedding 平均；多时间窗口向量召回池共享模型
- 类目/关键词召回：索引按时间倒排取最新；只对刚发布有效、弱个性化
- 聚类召回：内容向量（预训练 CNN/BERT + 可训练 FC）→ k-means 1000 cluster；种子笔记 → 最近 cluster → 最新笔记；triplet 训练
- Look-Alike：交互用户 = 种子用户，平均用户向量近线更新，向量库最近邻扩散；思想类似 UserCF
- 物品透出三阶段：类目/聚类（刚发布）→ Look-Alike（有点击不高）→ 双塔/ItemCF/Swing（点击高）
- 流量调控（冷启最重要一环）：强插 → 提权 → 保量 → 差异化保量
- 提权缺点：对系数敏感难控量；boost 过猛推给不合适受众、长期被系统打压
- 保量：24h 100 次曝光，动态提权 = f(时间进度, 曝光进度)；线上环境变化要重调；达标后停止扶持自然分发
- 差异化保量：基础 100 + 内容质量（≤+200）+ 作者质量（≤+200），最多 500
- 冷启 AB：用户侧只看消费指标，diff 推全会缩小；作者侧方案一（只分新笔记：互抢流量）、方案二（+分用户：池减半）、方案三（全分桶 = 两个 app：不可行）
