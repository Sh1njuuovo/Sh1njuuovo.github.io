## 1. 解码策略作用在哪里

```text
当前 token 序列 → 模型 → 最后位置的 logits
                            ↓
                    解码策略选出一个 token
                            ↓
                      追加到输入并继续
```

普通推理使用固定模型参数。Temperature、top-k、top-p 等调整的是如何使用输出分数，不进行反向传播或参数更新。

## 2. Greedy 与 Sampling

Greedy 每次选择最高分 token：

```python
next_id = last_logits.argmax(dim=-1, keepdim=True)
```

Softmax 保持大小顺序，因此 greedy 不必先算概率。

Sampling 先将 logits 变成概率，再按概率抽样：

```python
probs = torch.softmax(last_logits, dim=-1)
next_id = torch.multinomial(probs, num_samples=1)
```

高概率 token 更容易抽到，低概率 token 也有机会。抽到低概率候选不代表程序出错。

## 3. Temperature

对正温度 T：

$$
p_i=\operatorname{softmax}(z/T)_i
$$

- T<1：放大分数差距，概率更集中。
- T=1：原始分布。
- T>1：缩小分数差距，概率更平缓。
- 正温度不改变排序，因此最后若仍用 argmax，选择不变（忽略数值误差，最高分唯一时）。
- 公式不能直接除以 0；部分接口把 temperature=0 约定为 greedy。

调整温度不会更新模型参数。

## 4. Top-k

每步保留最高分的 k 个 token，屏蔽其他候选，重新归一化并抽取一个。

例如概率 `[0.5, 0.3, 0.15, 0.05]`，k=2 时：

```text
保留前两项 → 除以 0.8 → [0.625, 0.375, 0, 0]
```

Top-k 限制候选数量，每步仍只选一个 token。k=1 且最高分唯一时，结果与 greedy 相同。

## 5. Top-p（核采样）

按概率从高到低排序，保留累计概率达到或超过 p 的最小候选集合，再归一化采样。跨过阈值的那个 token 也要保留。

| Token | 示例概率 | 累计概率 |
|---|---:|---:|
| 苹果 | 0.50 | 0.50 |
| 音乐 | 0.30 | 0.80 |
| 电影 | 0.15 | 0.95 |
| 游戏 | 0.05 | 1.00 |

- p=0.7：保留苹果、音乐，重新归一化为 0.625、0.375。这道题已独立回答正确。
- p=0.9：还需保留电影，因为前两项累计只有 0.8。

Top-k 固定候选数量；top-p 根据当前分布动态调整候选数量。

## 6. Beam Search（束搜索）

Beam Search 同时维护 B 条候选序列，每轮扩展候选，并从全部扩展结果中统一保留累计分数最高的 B 条。

同样长度的序列可用条件概率连乘比较：

$$
P(y_1,\ldots,y_T\mid x)=\prod_{t=1}^{T}P(y_t\mid x,y_{<t})
$$

实际常用 log 概率相加，避免连乘导致数值过小。

### 两步示例

第一步 A=0.6、B=0.4；第二步在 A 后 X/Y 各为 0.5，在 B 后 X/Y 分别为 0.9/0.1：

| 序列 | 联合概率 |
|---|---:|
| A → X | 0.30 |
| A → Y | 0.30 |
| B → X | 0.36 |
| B → Y | 0.04 |

Greedy 第一步选 A，错过 B→X。Beam width=2 可以保留 A、B，扩展后发现 B→X 得分更高。

另一道例题：A→X 为 0.7×0.4=0.28，B→X 为 0.3×0.95=0.285，后者略高。该题由助手演算。

### 边界

- Top-k sampling 对一条前缀限制候选后抽一个；Beam Search 同时保留多条前缀。
- 有限 beam width 不保证全局最优，提前淘汰的前缀也可能有更好的后续。
- 原始概率连乘容易偏向短序列，比较不同长度时常加入长度惩罚或归一化。
- 遇到结束 token 的候选停止扩展；具体完成候选的保留与停止规则取决于实现。
- 高模型概率不直接等同于更符合用户需求的输出。

## 7. KV Cache：生成中复用历史计算

### Prefill 与 Decode

| 阶段 | 操作 |
|---|---|
| Prefill | 处理完整提示词，保存各层 K/V，并预测第一个新 token |
| Decode | 每轮处理新 token，读取历史 K/V，追加新 K/V，再预测后续 token |

在固定参数、位置和正常推理条件下，causal attention 的旧位置看不到新追加的 token，因此旧位置已有表示与各层 K/V 不会因追加而改变。

### 具体节省哪些计算

已经处理“我 喜欢 苹果”，并选出“手机”。下一轮：

| 计算 | 无缓存的完整重算 | 有 KV Cache |
|---|---|---|
| 旧 token 的各层 Q/K/V | 重新计算 | 复用缓存中的 K/V，无需旧 Q |
| 旧 token 的 Attention 输出 | 重新计算 | 无需重算 |
| 旧 token 的 MLP 输出 | 重新计算 | 无需重算 |
| 新 token 的各层计算 | 计算 | 仍要计算 |
| 新 token 对历史的注意力 | 计算 | 仍要计算 |

以一层单头为例，总长度为 4 时：

```text
无缓存：Q [4,d_k] × Kᵀ [d_k,4] → [4,4]
有缓存：Q [1,d_k] × Kᵀ [d_k,4] → [1,4]
```

每一层缓存各自的 K/V。新 token 在当前层算出 q/k/v，将 k/v 追加到缓存，用 q 匹配全部 K 并汇总全部 V，再经过该层其余计算进入下一层。

旧 Query 用于计算旧位置的输出，后续位置通常无需再使用，因此缓存重点是 K/V。

### 代价与使用场景

- 主要用于自回归推理；常规全序列训练通常不使用这种跨生成步骤的缓存。
- 训练为反向传播保存激活值，与推理 KV Cache 用途不同。
- 缓存通常随序列长度增长，消耗额外内存。
- 新 token 仍需要读取历史 K/V；上下文增长时，每轮的历史读取开销仍然增加。
- 本轮小 GPT 生成代码未使用 KV Cache，每轮重算完整前缀。

## 8. 解码实验与实际结果

实验脚本为学习时运行的 `experiments/decoding_demo.py`。使用固定 logits `[3, 2, 1, 0]`，对应苹果、音乐、电影、游戏，不加载或训练模型。

### 概率输出

| 策略 | 苹果 | 音乐 | 电影 | 游戏 |
|---|---:|---:|---:|---:|
| Temperature=0.5 | 0.865 | 0.117 | 0.016 | 0.002 |
| Temperature=1.0 | 0.644 | 0.237 | 0.087 | 0.032 |
| Temperature=2.0 | 0.455 | 0.276 | 0.167 | 0.102 |
| Top-k=2 | 0.731 | 0.269 | 0 | 0 |
| Top-p=0.9 | 0.665 | 0.245 | 0.090 | 0 |

Greedy 输出“苹果”。Top-k、top-p 两项分别作用于原始 logits，不是依次叠加前面的温度设置。

Top-p 中，原始前两项累计约 0.881，小于 0.9，因此还保留电影，再重新归一化。打印数值经过舍入。

### 独立采样输出

```text
['苹果', '苹果', '苹果', '苹果', '苹果', '苹果',
 '电影', '电影', '苹果', '苹果', '苹果', '苹果',
 '音乐', '音乐', '苹果', '苹果', '苹果', '音乐',
 '苹果', '苹果']
```

20 次中苹果 15 次、音乐 3 次、电影 2 次、游戏 0 次。小样本频率不要求等于理论概率，未抽到游戏也正常。

这里是在同一分布上独立抽样 20 次。真实连续生成每轮需要更新前缀，由模型重新给出下一轮分布。
