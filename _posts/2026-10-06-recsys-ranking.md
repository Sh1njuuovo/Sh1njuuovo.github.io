排序在召回之后，负责对候选物品打分排序，决定最终展示顺序。需要**多目标**：不仅要预估用户点不点，还要预估点赞、收藏、转发、观看时长等。

## 1. 多目标模型

### 用户与笔记的交互

在转化流程中提到过，用户与物品的交互可以作为推荐的依据。在小红书中，对每篇笔记系统记录曝光、点击、点赞、收藏、转发次数，由此计算消费指标，衡量一篇笔记受欢迎的程度：

```
点击率 = 点击次数 / 曝光次数     ← 唯一分母是曝光次数的指标
点赞率 = 点赞次数 / 点击次数
收藏率 = 收藏次数 / 点击次数
转发率 = 转发次数 / 点击次数     ← 转发很少，但是很重要
```

### 排序的依据

1. 排序模型预估点击率、点赞率、收藏率、转发率等多种**分数**
2. 融合这些预估分数（比如加权和，权重通常由 A/B 测试调整选出）
3. 根据融合分数做排序、截断

### 多目标模型结构

```
输入：用户特征 + 物品特征 + 统计特征 + 场景特征
        ↓
   Concatenation
        ↓
     神经网络（shared bottom）
        ↓
  点击率   点赞率   收藏率   转发率
  FC+Sigmoid × 4（每个目标一个输出头）
```

每个目标输出一个概率预估值，对应真实标签 y（0 表示无该动作、1 表示发生该动作）。模型相当于在解决**四个二分类问题**：判断用户是否点击、点赞、收藏、转发。

Tips：

- 统计特征包括用户和物品的统计特征，比如用户 30 天内点赞了多少笔记、候选物品 30 天内获得了多少次曝光
- 场景特征包括时间、地点等，候选物品在不同城市、季节、节假日下，用户的兴趣程度可能完全不同
- 在精排中，这里的神经网络被称为 shared bottom，是非常大、结构非常复杂的神经网络

### 模型训练

四个二分类都用交叉熵，总损失是各目标交叉熵的加权和：

```
L = Σ_{k=1..4} α_k · CrossEntropy(y_k, p_k)
```

其中 `CrossEntropy(y,p) = −(y·ln p + (1−y)·ln(1−p))`，超参数 α_k 是各损失的权重。对损失求梯度、做梯度下降更新参数。

### 困难：类别不平衡

- 每 100 次曝光，约 10 次点击、90 次无点击
- 每 100 次点击，约 10 次收藏、90 次无收藏

负样本数量远多于正样本。常见解决方案是**负样本降采样（down-sampling）**：

1. 保留一小部分负样本，让正负样本数量平衡
2. 减少负样本数量，节约计算

### 预估值校准

降采样后必须校准，否则预估值偏离真实值。以点击率为例推导：

- 设正样本 n⁺、负样本 n⁻
- 真实点击率：`p_true = n⁺ / (n⁺ + n⁻)`
- 负样本降采样，设采样率 α ∈ (0,1)，训练时用了 α·n⁻ 个负样本
- 预估点击率：`p_est = n⁺ / (n⁺ + α·n⁻)`（期望）——负样本变少、分母变小，所以 p_est > p_true

校准公式（推导略，可自己代几组数字验证）：

```
p_true = α · p_est / (1 − (1−α) · p_est)
```

> Tip：会有人问「只做排序的话，校准与否不影响相对顺序，为什么要校准？」原因有几点：
>
> 1. 只优化点击率一项时，降采样不改变物品之间的相对顺序，确实不影响排序；
> 2. 多目标模型涉及多个指标结果的相乘或加权，各指标预估值被降采样污染的程度不同，不校准无法统一量纲，融合结果会错；
> 3. 在广告系统中，点击率要参与广告计费，必须用校准后的精确值（广告侧的校准方法不限于此）。

## 2. MMoE（Multi-gate Mixture-of-Experts）

### 结构

MMoE 是对经典多目标模型的改进。基本思想：对于不同的目标，融合特征后用多个「专家」得到多个表征向量，同时为每个目标用神经网络算出一组权重，最后对专家向量做**加权平均**再输出预估值。

```
输入 x（用户/物品/统计/场景特征）
        ↓
  专家1   专家2   专家3     ← 三个神经网络（专家数 = 超参数）
        ↓
  对每个目标 k：softmax 门控给出权重 p_k1, p_k2, p_k3
  目标 k 的输入 = p_k1·专家1 + p_k2·专家2 + p_k3·专家3
        ↓
  点击率头 / 点赞率头 / ...
```

Tips：

- 图中的第 1、2、3 号神经网络就是三个「专家」（experts）。专家数 n 是超参数，实际训练中多会尝试 4 个和 8 个的情况
- 有 n 个专家时，每个专家输出一个向量，softmax 的输入和输出都是 n 维向量
- 多个目标需要对应数量的门控神经网络组合，来算不同权重和预估值

### 极化现象（Polarization）

现实应用中使用 Softmax 会不可避免地出现极化：

- 极化（polarize）：softmax 的输出一个接近 1、其余接近 0
- 例如某目标的门控输出接近 one-hot，后续计算相当于只用了某一个专家；其他专家在训练中没起作用，相当于 dead 了，Mixture-of-Experts 的意义就失去了

### 解决极化：门控输出 dropout

训练时对 softmax 的输出使用 dropout：

- softmax 输出的 n 个数值被 mask 的概率都是 10%
- 也就是每个专家被随机丢弃的概率都是 10%
- 每个任务只用部分专家做预测，迫使每个专家都参与训练，避免某个专家长期不被选中

参考文献：Ma et al., MMoE, KDD 2018；Zhao et al., YouTube 多任务排序（提出极化问题解决方案）, RecSys 2019。

## 3. 预估分数的融合

通过多目标模型得到点击率、点赞率、收藏率等预估值后，排序前需要融合这些分数。常见方法如下：

**1. 简单的加权和**

```
score = p_ctr + w₁·p_like + w₂·p_collect + ...
```

**2. 点击率乘以其他项的加权和**

```
score = p_ctr × (1 + w₁·p_like + w₂·p_collect + ...)
```

由指标计算公式可知，p_like = 点赞次数/点击次数，乘上 p_ctr 之后相当于把其他项的分母从点击次数替换成了曝光次数，语义变成「每次曝光期望带来的互动」。

**3. 海外某短视频 App 的融分公式**

```
score = (1 + w₁·p_like) × (1 + w₂·p_comment) × ...
```

其中还包括对观看时长的预估等项；w₁、w₂、β 等都是超参数，需要通过 A/B 测试调整。

**4. 国内某短视频 App 的融分公式（Ensemble Sort）**

1. 根据预估时长 p_watch，对 n 篇候选视频排序
2. 某视频排名第 r，则该项得分为 w/(r + β)——时长越长、排序越靠前，得分越高
3. 对点击、点赞、转发、评论等预估分数做类似处理
4. 对以上处理后的分数做加权和，得到最终融合分数

```
score = Σ wᵢ / (rᵢ + βᵢ)
```

**5. 某电商的融分公式**

1. 电商转化链路：曝光 → 点击 → 加购物车 → 付款
2. 模型预估：点击率 p_click、加购物车率 p_cart、付款率 p_pay
3. 最终融合分数：

```
score = p_click^w₁ × p_cart^w₂ × p_pay^w₃ × price^w₄
```

> 融分没有标准答案。不同产品的链路和业务目标不同，但核心一致：各指标量纲不同、业务价值不同，需要加权或级联地合成最终分；权重基本靠 A/B 测试调。

## 4. 视频播放建模

图文笔记的排序依据包括点击、点赞、收藏、转发、评论等；视频排序还要看**播放时长**和**完播率**，而且对视频来说这两个指标的重要性远高于其他指标。

### 视频播放时长

播放时长是连续变量，但**直接用回归拟合效果不好**，建议用 YouTube 的时长建模：

1. 设模型最后一个全连接层的输出为 z，对 z 做 sigmoid 得到 p = sigmoid(z)
2. 设真实播放时长为 t（没点击则 t=0），训练目标让 p 拟合 t/(1+t)，使用（加权）交叉熵损失：

```
L = − t/(1+t) · log p − 1/(1+t) · log(1−p)
```

3. 观察 p 与 t 的关系：如果 p = t/(1+t)，则 exp(z) = t。所以在推理时，**exp(z) 就是对播放时长 t 的预估**（不是 p）
4. 把 exp(z) 作为融分公式中的一项

### 视频完播率

两种建模方法：

**回归方法**：用预估播放率 p 拟合实际播放率 y（例：10 分钟视频播放 4 分钟，y = 0.4），损失为 `y·log p + (1−y)·log(1−p)`。线上输出 p = 0.73，意思是预计播放 73%。

**二元分类方法**：定义完播指标（如播放 >80% 算完播），播放 >80% 是正样本、<80% 是负样本，做二分类。线上输出 p = 0.73，意思是 P(播放 >80%) = 0.73。

**不能直接把预估完播率用于融分公式**：视频越长完播率越低，模型训练没有考虑时长影响，直接比 p 不能平等对待长短视频。处理方式：

1. 先用函数 f(视频长度) 拟合「该时长视频的基准完播率」
2. 线上调整：`p_调整后 = p_预估 / f(视频长度)`
3. 把调整后的值作为融分公式中的一项

## 5. 排序模型的特征

### 特征类别

召回和排序都要用用户和物品的多维特征，分为五类：

| 特征类别 | 特征描述 |
| --- | --- |
| 用户画像（User Profile） | ① 用户 ID（召回、排序中做 embedding，常用 32 维和 64 维）；② 人口统计学属性：性别、年龄；③ 账号信息：新老、活跃度；④ 感兴趣的类目、关键词、品牌 |
| 物品画像（Item Profile） | ① 物品 ID；② 发布时间（或年龄）；③ GeoHash、所在城市；④ 标题、类目、关键词、品牌；⑤ 字数、图片数、视频清晰度、标签数；⑥ 内容信息量、图片美学 |
| 用户统计特征 | ① 用户最近若干时间窗口的曝光数、点击数、点赞数、收藏数；② 按笔记图文/视频分桶；③ 按笔记类目分桶 |
| 笔记统计特征 | ① 笔记最近若干天的曝光数、点击数、点赞数、收藏数；② 按用户性别、年龄分桶；③ 作者特征：发布笔记数、粉丝数、消费指标 |
| 场景特征（Context） | 随推荐请求传来，不从用户/物品画像获取：① 定位 GeoHash、城市；② 当前时刻（分段做 embedding）；③ 是否周末、节假日；④ 手机品牌、型号、操作系统 |

Tips（对应表中的注释）：

- **新老、高低活用户**的行为差距很大，模型需要针对做专门优化
- 笔记发布时间越久价值越低，尤其与新闻舆论相关的时效性只有几天
- 用户统计特征分桶示例：最近 7 天该用户对图文笔记、视频笔记各自的点击率
- 笔记统计特征分桶示例：最近 30 天用户对美妆、美食、数码类笔记的点击率
- 作者特征反映作者的受欢迎程度和作品的平均品质
- 安卓和 iOS 的指标差异特别大，手机型号是重要场景特征

### 特征处理

| 特征类型 | 处理方式 | 特征描述 |
| --- | --- | --- |
| 离散特征 | 做 embedding | 用户 ID、笔记 ID、作者 ID（消耗内存较大）；类目、关键词、城市、手机品牌 |
| 连续特征 | 做分桶，变成离散特征 | 年龄、笔记字数、视频长度 |
| 连续特征 | 其他变换 | 曝光数、点击数等做 log(1+x)；转化为点击率、点赞率等值，并做平滑 |

- log(1+x) 变换针对长尾数据，可以压低异常值的影响
- 除了异常值，还要考虑**特征覆盖率**：大多数特征覆盖不了 100% 样本（不填年龄、开隐私权限拿不到定位等），提高覆盖率可以让精排模型更准，处理时还要考虑缺失值补全

### 数据服务（简要）

线上请求时，排序服务器从数据服务取特征：用户画像较为静态、物品画像静态、统计数据动态。取齐特征后做特征打包，送进 TF Serving 推理。

## 6. 粗排

本章前序内容主要描述精排模型，本节单独介绍粗排。

### 粗排 vs 精排

| | 粗排 | 精排 |
| --- | --- | --- |
| 任务 | 给几千篇笔记打分 | 给几百篇笔记打分 |
| 推理代价 | 单次推理代价必须小 | 单次推理代价可以很大 |
| 准确性 | 预估准确性不高 | 预估准确性更高 |

### 精排模型 vs 双塔模型

| | 精排模型 | 双塔模型 |
| --- | --- | --- |
| 融合方式 | **前期融合**：先对所有特征做 concatenation，再输入神经网络 | **后期融合**：用户、物品特征分别输入不同神经网络，不做交叉融合 |
| 推理代价 | 大：n 篇候选，整个大模型要做 n 次推理 | 小：用户塔只做 1 次线上推理；物品向量线下算好存数据库，物品塔线上不推理 |

双塔的预估准确性不如精排。**后期融合适合快速召回，前期融合适合精准排序。**

### 粗排的三塔模型（COLD）

小红书粗排用三塔模型，效果介于精排和双塔之间。输出、训练与精排完全一致，主要区别在下面的三个塔——介于前期融合和后期融合之间：

| 塔 | 大小 | 输入 | 设计原因 |
| --- | --- | --- | --- |
| 用户塔 | 很大 | 用户特征、场景特征 | 只有一个用户，只做 1 次推理，即使塔很大总计算量也不大 |
| 物品塔 | 较大 | 物品特征（静态） | n 个物品理论上做 n 次推理，所以要缓存输出向量，避免绝大部分推理 |
| 交叉塔 | 较小 | 统计特征、交叉特征（动态） | 统计特征动态变化、缓存不可行，且必须做 n 次推理，所以交叉塔必须小 |

模型上层（Concatenation & Cross → 各目标 Sigmoid 头）对 n 个物品做 n 次推理，上层推理的计算量高于交叉塔，是粗排的大部分计算量所在。

三塔模型推理总结：

1. 从多个数据源取特征：1 个用户的画像、统计特征 + n 个物品的画像、统计特征
2. 用户塔：只做 1 次推理
3. 物品塔：未命中缓存时才需要推理
4. 交叉塔：必须做 n 次推理
5. 上层网络做 n 次推理，给 n 个物品打分

参考文献：Wang et al., *COLD: Towards the Next Generation of Pre-Ranking System*, DLP-KDD 2020。

## 7. 本章小结

本篇主要记录排序中的粗排模型与精排模型。

精排模型为**多目标模型**：先融合用户和物品的多个特征输入神经网络（shared bottom），输出各指标的预估值（前期融合）。训练时把问题转化为多个二分类，用交叉熵损失；类别不平衡时负样本降采样；训练后要做预估值校准。

在精排的基础上提出 **MMoE**：对不同目标，先用多个专家得到多个表征向量，再用门控神经网络算权重，对向量做加权平均输出预估值。由于使用 softmax 会出现极化，用 dropout 强迫每个专家都参与训练决策。

小红书粗排是**三塔模型**：与精排的区别在于下层先通过塔得到特征向量再融合输出，是介于前期融合（精排）和后期融合（双塔）之间的思想，有利于快速推理、降低线上计算代价。

以上模型架构不同，但同属排序模型、训练方式相同：收集多维特征并做特征处理（embedding、异常值、缺失值），用交叉熵做多目标分类训练，训练后校准，上线后用融分公式合成多个预估值再排序。

视频场景需要额外对**播放时长和完播率**建模，并给出对应的训练、推理和校准方式。

## 复习速记

- 多目标排序：shared bottom + 每目标一个 FC+Sigmoid 头；总损失 = Σ α_k·CE(y_k, p_k)；本质是四个二分类
- 类别不平衡 → 负样本降采样 → 预估值偏高 → 校准 `p_true = α·p_est / (1 − (1−α)·p_est)`
- 为什么校准：单指标排序序不变，但多目标融合量纲不统一、广告要精确计费
- MMoE：专家 + 每任务 softmax 门控；极化（门控 one-hot、专家死亡）→ 门控输出 dropout（每专家 10% 被 mask）
- 融分：加权和 / p_ctr×(1+加权和)（把点赞等分母从点击换成曝光）/ 海外短视频乘积式 / 国内短视频 Ensemble Sort 排名式 Σ w/(r+β) / 电商 p_click^w1·p_cart^w2·p_pay^w3·price^w4；权重 A/B 调
- 视频时长用 YouTube 方法：训练加权交叉熵（t/(1+t) 做标签权重），推理用 exp(z) 当预估时长
- 完播率：回归或二分类；直接用会偏向短视频，除以 f(视频长度) 校准
- 特征五类：用户画像、物品画像、用户统计、物品统计、场景特征；离散做 embedding，连续分桶或 log(1+x)，比例值做平滑；注意覆盖率与缺失值
- 粗排三塔（COLD）：用户塔大但只推理 1 次；物品塔靠缓存；交叉塔处理动态特征、必须小；计算大头在上层 n 次推理
- 前期融合（精排）精度高代价大；后期融合（双塔）代价小精度低；三塔模型介于两者之间
