## 1. 推荐系统基本概念

可以将一个**推荐系统**简单地理解为**给用户推荐实体或非实体物品的系统**。其任务是根据用户和物品的特征，使用某种或某些推荐算法预测任意用户对任意物品的兴趣得分，并按照预测的得分顺序，将排在前列的物品展示给用户。

> Tip：以小红书为例，物品为小红书笔记，后续统一使用物品进行描述。

### 转化流程

根据不同公司的不同产品，一般有不同的转化流程。流程中的动作意味着**用户对物品感兴趣**，这些动作意味着**用户和物品产生了交互**，可以作为**推荐系统使用的推荐依据**。转化流程一般分为三步，以小红书为例：

```
曝光 (Impression) → 点击 (Click) → 阅读 → 互动
                                     ├── 滑动到底 (ScrollToEnd)
                                     ├── 评论 (Comment)
                                     ├── 点赞 (Like)
                                     ├── 收藏 (Collect)
                                     └── 转发 (Share)
```

> Tip：抖音没有点击流程（视频曝光即开始播放）。

### 常见的推荐系统评测指标

消费指标（短期）与北极星指标（长期）的对应关系：

| 消费指标（短期消费指标） | 北极星指标（长期消费指标） |
| --- | --- |
| 基于点击的指标：点击率 | 基于用户规模：日活用户数（DAU）、月活用户数（MAU） |
| 基于反馈的指标：点赞率、收藏率、转发率 | 基于消费用户：人均使用推荐时长、人均阅读笔记数量 |
| 基于特定产品的指标：阅读完成率（文章） | 基于发布用户：发布渗透率、人均发布量 |

各指标的定义（分母不同，别记混）：

| 指标 | 公式 |
| --- | --- |
| 点击率 (CTR) | 点击次数 / 曝光次数 |
| 点赞率 | 点赞次数 / 点击次数 |
| 收藏率 | 收藏次数 / 点击次数 |
| 转发率 | 转发次数 / 点击次数 |
| 阅读完成率 | 滑动到底次数 / 点击次数 × 笔记长度系数 f |

**消费指标并不是推荐系统追求的根本目标**，考察的关键应该放在北极星指标上。只追求极致的消费指标提升，最直接的影响就是导致推荐给用户的物品都是相似或相同的，显著减少了推荐的多样性，用户很难接触到感兴趣但新鲜的物品，长久以往用户活性降低，用户不断流失。在实践中，消费指标降低但是北极星指标提升也被认为是一种正向的趋势。

> Tip：发布是小红书的核心竞争力。

### 推荐系统的实验流程

```
离线实验 → 小流量 A/B 测试 → 全流量上线
```

- **离线实验**：收集历史数据在其上做模型训练和测试，算法没有部署到产品中，没有跟用户交互
- **小流量 A/B 测试**：把算法部署到产品中，设置实验组与对照组使用新旧策略，算法与部分用户做交互
- **全流量上线**：A/B 测试的新策略优于旧策略，就加大交互的用户流量，最后推全

## 2. 推荐系统的链路

推荐系统目标：从几亿物品中选取几十个物品推荐给用户。

```
几亿物品 → 召回 → 几千 → 粗排 → 几百 → 精排 → 几百 → 重排 → 几十
```

- **召回**：用多条召回通道（协同过滤、双塔模型、关注的作者等），先快速取回几千物品。召回通道实际上就是实现召回的模型方法，第二章会详细介绍
- **粗排**：用小规模神经网络，给几千篇物品打分，选出分数 Top 几百的物品
- **精排**：用大规模神经网络，给粗排选出的几百篇物品重新打分排序。输入包括用户特征、物品特征、统计特征，输出点击率、点赞率、收藏率、转发率等多个预估值（多任务）
- **重排**：多样性抽样（如 MMR、DPP）从几百篇物品中挑选几十篇，依规则打散相似物品，并插入广告和运营物品，根据生态再调整排序

> 一句话总结：**召回负责找全，粗排精排负责算准，重排负责摆好。**

## 3. 推荐系统的 A/B 测试

召回团队实现了一种新的召回通道（如 GNN 召回），离线实验结果是正向的，下一步就需要做线上的小流量 A/B 测试。A/B 测试起到如下作用：

1. 考察新的召回通道对线上指标的影响；
2. 测试选择模型的最优参数（如 GNN 深度取 1、2、3）。

### 随机分桶

A/B 测试需要设置对照组和实验组，对照组和实验组通过随机分桶来实现。不妨设全部 n 位用户，分成 b 个桶（如 b=10），每个桶有 n/b 位用户。随机分桶实现原理如下：

1. 首先使用哈希函数将用户 ID 映射成某个区间内的整数，然后把这些整数均匀随机分成 b 个桶；
2. 可以取其中若干个桶作为多个实验组采用不同的召回通道，再另取一个桶为对照组使用原策略；
3. 计算每个桶的业务指标（如 DAU、人均使用推荐时长、点击率等）；
4. 如果某个实验组显著优于对照组，则说明对应的策略有效，值得推全。

> Tip：从统计学角度出发，如果样本足够大，可以认为各个桶的特征相同。

### 分层实验

互联网大厂这种信息流公司有很多的团队和部门，需要同时负责推荐系统（召回、粗排、精排、重排）、用户界面、广告等业务的 A/B 测试。此时会遇到用户流量不够用的情况（10 个桶最多只能同时做 9 组实验），分层实验是一项很好的举措：

- **分层**：分成召回、粗排、精排、重排、用户界面、广告等多个层
- **同层互斥**：某召回实验占用了召回层的 4 个桶，其他召回实验只能使用剩余的 6 个桶
- **不同层正交**：每一层独立随机对用户做分桶，每一层都可以独立使用 100% 的用户做实验

基于以上原理，以召回层和精排层为例说明。假设系统共有 n 个用户，召回层将用户分成了 10 个桶 U₁...U₁₀，精排层也独立将用户分为 10 个桶 V₁...V₁₀，那么：

1. 任意召回桶 Uᵢ 和精排桶 Vⱼ 均满足 |Uᵢ| = |Vⱼ| = n/10；
2. 同层互斥：不同的召回桶 Uᵢ 和 Uⱼ 的交集为 ∅；
3. 不同层正交：召回桶 Uᵢ 和精排桶 Vⱼ 的交集大小为 n/100。

> 推导：上一层每个桶中的用户被均匀分到下一层 10 个桶中，相当于上下任意两桶中只有 1/10 比例的用户是相同的；再考虑到任意桶中只有 n/10 个用户，所以上下两层任意两桶中只有 n/10 × 1/10 = n/100 个相同用户。

既然分层实验可以有效处理流量不足问题，那么是否所有实验都正交、可以同时做无数组实验？答案是否定的，原因如下：

1. 同类的策略（比如召回层的不同通道）天然互斥，对于同一用户只能使用其中一种；
2. 同类的策略可能相互抵消（1+1<2）或相互增强（1+1>2），互斥可以避免同类策略相互干扰；
3. 不同类的策略（比如添加召回通道和优化粗排模型）通常不会相互干扰（1+1=2），才可以做正交的两层。

参考：Tang et al., *Overlapping Experiment Infrastructure*, KDD 2010。

### Holdout 机制

公司需要考察部门（如推荐系统）在一段时间内对业务指标的总体提升，而每个实验（召回、粗排、精排、重排）只独立汇报对业务指标的提升贡献，因此设置了 Holdout 机制，基本思想为：

1. 取 10% 的用户作为 Holdout 桶，推荐系统使用剩余 90% 的用户做实验，两者互斥；
2. 考察 10% Holdout 桶与 90% 实验桶的差异（需归一化），作为整个部门的业务指标收益；
3. 每个考核周期结束之后，清除 Holdout 桶，让推全实验从 90% 用户扩大到 100% 用户；
4. 重新随机划分用户，得到 Holdout 桶和实验桶，开始下一轮考核周期；
5. 初始的新 Holdout 桶与实验桶的各种业务指标的差异接近 0，随着召回、粗排、精排、重排实验上线和推全，差异会逐渐扩大。

### 实验推全和反转实验

**实验推全**：在 Holdout 机制基础上，观测到某个策略对业务指标有明显提升，关闭 A/B 测试，将策略推全到整个 90% 用户上。需要在召回层之前新建一个推全层，该层与其他层正交。

**反转实验**：为了尽快推全新策略、同时长期观测实验指标，需要在推全的新层中设立一个旧策略的桶（反转桶），长期观测实验指标。

1. 点击、交互这类指标会立刻受到新策略的影响，而留存这类指标具有滞后性，需要长期观测；
2. 实验观测到显著收益后需要尽快推全新策略，腾出桶给其他实验使用，或基于新策略尽快进行后续开发。

> Tip：推全层中推全新策略的桶和使用旧策略的反转桶是互斥的；推全层与 Holdout 桶无关，考核周期结束后清除 Holdout 桶不会影响反转桶。反转实验结束后关闭反转桶，真正做到推全到 100% 用户。

## 4. 本章小结

推荐系统是给用户推荐实体或非实体物品的系统。

本章首先依次介绍了**推荐系统的基本概念**、**推荐依据**、**评价指标**、**链路**、**实验流程**；然后针对实验流程中的 **A/B 测试**进行了知识扩充，详解了**随机分桶**、**分层实验**、**Holdout 机制**、**实验推全**和**反转实验**的概念与思想。这些基础知识将贯穿后续所有章节内容。

## 复习速记

- 推荐漏斗各层数量级和职责：召回（几亿→几千，多路召回）、粗排（→几百，小模型）、精排（→几百，大模型多任务）、重排（→几十，多样性/打散/插广告）
- 消费指标分母：点击率用曝光次数，其余（点赞率/收藏率/转发率/阅读完成率）用点击次数；阅读完成率还要乘笔记长度系数 f
- 消费指标是短期指标，北极星指标才是根本目标；过度优化消费指标会损害多样性、导致用户流失
- 实验流程：离线实验 → 小流量 A/B → 全流量上线
- A/B 测试核心概念：随机分桶、同层互斥、跨层正交、Holdout 桶、反转实验
- 为什么要分层实验：多团队共用流量；同类策略互斥防干扰，异类策略正交不干扰（1+1<2 或 >2 vs 1+1=2）
- 为什么需要 Holdout：单个实验只看自身提升，部门整体收益要通过 10% vs 90% 的归一化 diff 衡量
- 为什么要反转实验：交互类指标即时可见，留存类指标有滞后性；推全腾桶和长期观测两个诉求靠反转桶同时满足
