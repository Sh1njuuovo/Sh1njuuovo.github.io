## 1. 一句话理解推荐系统

推荐系统的任务：从海量的候选物品里，为每个用户在特定场景下挑出几十条最可能让他感兴趣、同时对公司有价值的物品，按合理顺序展示给他。

场景里「物品」可以是：小红书笔记、抖音视频、淘宝商品、公众号文章……

决定推荐效果的三方输入：

- **用户**：画像（年龄、性别）、历史行为（点过什么）、当前状态（时间、地点、设备）
- **物品**：内容（图文/视频）、属性（类目、作者、价格）、统计（热度）
- **场景/上下文**：时间、位置、是否节假日、页面位置

## 2. 宏观链路（记忆主线）

```
用户行为数据 → 样本构造 → 召回候选 → 排序打分 → 重排 → 离线/线上评估
                                    （粗排 → 精排）
```

对应到真实系统里，一次刷新背后的规模变化是：

```
几亿物品 ──召回──> 几千 ──粗排──> 几百 ──精排──> 几百 ──重排──> 几十
```

每一环要回答的问题：

| 环节 | 做什么 | 输入 → 输出 | 关键词 |
| --- | --- | --- | --- |
| 数据 | 记录用户行为日志 | 曝光、点击、点赞、收藏、转发、评论、关注、时长 | 反馈 = 信号 |
| 样本构造 | 把日志变成可训练的数据 | 正样本（曝光且点击）+ 负样本 | 正负样本、采样 |
| 召回 | 快速捞回可能感兴趣的候选 | 几亿 → 几千 | 多路召回、ANN |
| 排序 | 精细打分排序 | 几千 → 几百（粗排）→ 几十（精排输出候选） | 多目标、特征交叉 |
| 重排 | 在几十里选最终展示、控制体验 | 几百 → 几十 | 多样性、规则、广告 |
| 评估 | 判断改得好不好 | 离线指标 + 线上 A/B | AUC/HR/NDCG、DAU/留存 |

> 核心矛盾贯穿始终：**候选量越大越全，但算得越慢**。所以链路越靠前越要快而粗，越靠后越可以慢而精。

## 3. 逐环细看

### ① 用户行为数据

用户和物品的每一次交互都是信号：

- 曝光（我们看到这条内容）→ 点击 → 阅读/播放 → 点赞/收藏/转发/评论/关注
- 信号强度不同：点击最弱、关注和转发较强；没点击 ≠ 不喜欢（可能只是没刷到或没兴趣点）

行为是几乎所有模型的地基：协同过滤靠「谁和谁共同喜欢」、双塔靠「点击对」、序列模型靠「用户最近看过什么」。

### ② 样本构造

模型训练前，要把行为日志变成 `(用户, 物品, 标签)`：

- **正样本**：曝光且点击（用户确实感兴趣）
- **负样本**：难点所在。常见有简单负样本（随机/全体物品）、困难负样本（被召回但排序淘汰的）、batch 内负样本（同批其他正样本当负样本）
- 常见坑：**曝光未点击**适合当排序负样本，却不适合当召回负样本（用户可能只是没来得及点）
- 特征：用户画像、物品画像、统计特征、场景特征 → 离散特征做 embedding、连续特征做归一化/分桶

### ③ 召回（几亿 → 几千）

目标：宁可多捞，不能漏掉用户可能感兴趣的。常用**多路召回**并行，各路结果合并：

- **协同过滤**：ItemCF（喜欢 A 的人还喜欢 B）、UserCF（相似的人喜欢什么）、Swing（降小圈子权重）
- **向量召回（双塔）**：把用户、物品各编码成一个向量，用相似度检索；这是目前召回主力
- **规则/内容通道**：类目、关键词、作者关注、地理位置、缓存
- **冷启动特例**：新物品没有行为，需要 default embedding、内容聚类、Look-Alike 等特殊通道

线上召回用**近似最近邻（ANN）**而不是暴力枚举（Faiss、Milvus、HNSW）。

### ④ 排序（几千 → 几十）

目标：把召回结果按「用户到底多想要」精细排序。

- **粗排**：候选几千，模型必须快（向量双塔、三塔 COLD），先砍到几百
- **精排**：候选几百，可以用大模型，做 **CTR / CVR 预估**（点不点、买不买、赞不赞……）
- 精排一般是**多目标模型**：同时预估点击率、点赞率、收藏率、转发率、评论率、关注率等，再按业务目标融合成一个分数
- 为了学得准，精排里会叠各种结构：用户行为序列（DIN/SIM）、特征交叉（DCN/DeepFM）、多任务门控（MMoE）

### ⑤ 重排（几百 → 最终几十）

目标：精排是「每篇单独值多少」，重排管「放在一起怎么排」：

- **多样性**：避免一屏全是同一类内容（MMR、DPP）
- **规则约束**：图文/视频间隔、运营推广数量限制、电商卡片控制
- **生态/商业**：插入广告和运营内容

### ⑥ 评估（离线 + 线上）

改一个模型之前先离线测，再线上小流量验证：

- **离线评估**：在历史数据上算指标（AUC、HR、NDCG 等）
- **线上 A/B**：随机分桶，实验组 vs 对照组，看业务指标（点击率、使用时长、DAU、留存）
- **推全**：A/B 显著正向后才全量上线；有 holdout 桶衡量部门整体贡献

注意：离线指标好 ≠ 线上一定好，因为离线数据是历史策略产生的，存在偏差。

## 4. 术语地图：把名词挂到链路上

逐个概念一句话定位（「→」指向详细章节笔记）：

| 概念 | 一句话理解 | 在链路中的位置 |
| --- | --- | --- |
| 协同过滤（ItemCF/UserCF/Swing） | 用「共同喜欢」统计相似度做推荐，经典召回方法 | 召回 → [02-retrieval](/posts/recsys-retrieval/) |
| 矩阵分解 / 矩阵补全 | 协同过滤的向量版：用户、物品各学低维向量，内积预测兴趣 | 召回思想源头 → 02 |
| Embedding | 把 ID/离散特征映射成稠密向量，全链路的地基 | 样本/特征 → 02、03 |
| 双塔模型 | 用户塔、物品塔分别编码，余弦相似度打分，召回主力 | 召回 → 02 |
| 负采样 | 召回训练时怎么选负样本（简单/困难/batch 内） | 样本构造 → 02 |
| ANN 向量检索 | 用索引近似找最近邻，代替暴力枚举 | 召回线上服务 → 02 |
| DIN / DIEN / SIM | 用户行为序列建模：DIN 用注意力加权历史；DIEN 加时间序列；SIM 处理超长序列 | 精排特征 → 05 |
| DeepFM | FM 深度化（低阶线性/交叉 + 高阶神经网络），CTR 常用模型（本课程未展开） | 排序特征交叉 |
| DCN | 显式交叉网络，可替换塔内网络结构 | 排序结构 → 04 |
| MMoE | 多任务学习的专家门控，缓解目标冲突 | 精排多目标 → 03 |
| CTR / CVR 预估 | 预估点击率 / 转化率，是排序模型的核心任务 | 精排 → 03 |
| 多目标融合 | 把点击/点赞/时长等预估值加权或相乘成最终分 | 精排输出 → 03 |
| 冷启动 | 新用户/新物品没有行为怎么推 | 贯穿召回/排序/流量 → 07 |
| MMR / DPP | 多样性重排算法 | 重排 → 06 |

## 5. 一次请求串起来（例子）

以小红书下拉刷新为例，可以把一次推荐请求记成以下步骤：

1. 取得用户 ID 和当前场景（时间、定位、设备）
2. **召回**：几十路通道并行——双塔使用最近的兴趣向量、协同过滤参考历史交互的笔记、关注的作者发的新笔记、同城内容……合并出几千候选
3. **粗排**：小模型把几千快速砍到几百
4. **精排**：大模型对几百篇做多目标打分（点击率、点赞率、收藏率……），融合成 reward 排序
5. **重排**：用规则 + 多样性算法（MMR/DPP）选出几十篇，插入广告和运营内容
6. 返回结果渲染；用户的点击、停留、点赞等行为被打进日志，成为明天训练数据的一部分

这就是「用户行为数据 → 样本构造 → 召回 → 排序 → 重排 → 评估」的一次完整闭环。

## 6. 概念演进主线（帮助记忆）

```
协同过滤（数人头）
   ↓ 向量化
矩阵分解（ID embedding + 内积）
   ↓ 加特征、解耦
双塔模型（用户塔/物品塔 + 余弦）
   ↓ 加序列行为、交叉结构、多目标
DIN/SIM、DCN/DeepFM、MMoE（精排模型不断变强）
   ↓ 业务侧补全
冷启动、多样性、流量调控、特殊人群（让链路可用、指标可涨）
```

复习时，我会用这条主线梳理几个常见问题：

- 为什么召回用双塔、精排用 concat 大模型？→ 前期融合 vs 后期融合的精度/算力取舍
- 为什么矩阵分解效果差？→ 只用 ID、负样本错、训练方式差
- 为什么精排要行为序列 + 特征交叉？→ 单点特征不够表达兴趣和组合信号
- 为什么排序完还要重排？→ pointwise 打分保证不了多样性

## 7. 指标总地图

一句话框架：**指标分两层——离线看「模型好不好」，线上看「产品好不好」；线上又按对象分「用户侧 / 作者侧 / 内容侧」，按时间分「短期 / 长期」。**

**第一层：模型离线指标（训练时内部用）**

| 指标 | 看什么 | 用在哪个环节 |
| --- | --- | --- |
| Recall@k / HR | top-k 有没有命中真实交互的物品 | 召回 |
| AUC | 正样本是否整体排在负样本前面（随机正负对，正样本分更高的概率） | 排序模型（CTR 等二分类） |
| NDCG | 命中的位置是否靠前（位置加权，越靠前分越高） | 精排、重排 |

- 作用：离线筛选模型版本；离线涨不代表线上涨，只做内部对比
- 粗略记忆：AUC 看整体排序能力，HR 看有没有命中，NDCG 看命中在不在前面

**第二层：业务线上指标（产品决策用）**

| 对象 | 指标 | 含义 |
| --- | --- | --- |
| 用户侧·消费（短期） | 点击率、点赞率、收藏率、转发率、完播率、使用时长 | 立刻见效、改动马上能测 |
| 用户侧·大盘（长期核心） | DAU / MAU、人均使用时长、人均阅读量 | 平台整体健康度 |
| 用户侧·留存（长期最核心） | LT7、LT30 | 用户留不留，最核心的指标 |
| 作者侧（UGC 核心） | 发布渗透率、人均发布量 | 内容供给积极性 |
| 内容侧 | 高热笔记占比 | 系统挖掘优质内容的能力 |

**关键优先级判断**

- 最核心 = **DAU + 留存**，UGC 平台再加**发布量**；CTR 这类反而不是核心
- 短期 vs 长期：短期（点击/交互）是过程信号，长期（留存/DAU/发布）是最终裁判；两者冲突时听长期的——短期降、北极星升也算正向
- 召回看 HR，排序看 AUC/NDCG，业务成败看 DAU/留存——**离线指标负责筛模型，A/B 业务指标负责做决定**
