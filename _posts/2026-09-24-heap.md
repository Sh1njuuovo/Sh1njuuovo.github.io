## 一句话概括

堆是一个能随时看到堆顶元素、并且增删都很快的容器。最小堆的堆顶是最小值，最大堆的堆顶是最大值。它不保证全部元素有序，只保证堆顶最值，所以比排序便宜。

## 什么时候用它

看到下面这些描述，先想想堆。

- 求第 k 大、第 k 小、前 k 个
- 数据一直在变，但每次只要当前的最大或者最小
- 一边遍历一边淘汰，只保留最新的 k 个
- 数据流里随时查询中位数这类统计量

## Python 基础

### heapq 只有最小堆

```python
import heapq

heap = []
heapq.heappush(heap, 5)          # 入堆
heapq.heappush(heap, 1)
heapq.heappush(heap, 3)

root = heap[0]                   # 看堆顶，得到 1
smallest = heapq.heappop(heap)   # 弹出堆顶，得到 1

heapq.heapify(nums)              # 把列表原地变成堆
```

`heap` 本身就是一个 list，只是满足堆的性质。`heap[0]` 是堆顶，`heap[1]` 和 `heap[2]` 之间没有大小关系，要按顺序取只能靠反复 `heappop`。

### 常用操作和复杂度

| 操作 | 写法 | 复杂度 |
| --- | --- | --- |
| 建堆 | `heapq.heapify(nums)` | O(n) |
| 入堆 | `heapq.heappush(heap, x)` | O(log n) |
| 出堆 | `heapq.heappop(heap)` | O(log n) |
| 看堆顶 | `heap[0]` | O(1) |
| 先弹后压 | `heapq.heapreplace(heap, x)` | O(log n) |
| 先压后弹 | `heapq.heappushpop(heap, x)` | O(log n) |
| 取前 k 大 | `heapq.nlargest(k, nums)` | O(n log k) |

建堆是 O(n)，因为调整从下往上做，大部分节点都在底层，需要下沉的距离很短，总的代价是线性的。

### 最大堆要存负数

Python 没有最大堆，标准做法是把数字取负再放进去。

```python
heap = []
heapq.heappush(heap, -5)
heapq.heappush(heap, -1)
largest = -heapq.heappop(heap)     # 得到 1
```

加负号之后，原来最大的数变成了最小的，最小堆的堆顶正好是它。取出来时再取一次负还原。

### 元组进堆的坑

堆里放元组时，先比第一个元素，相等再比第二个。347 题用的就是 `(次数, 数字)` 这种形式。

如果第二项不能比较大小，比如是列表、字典或者自定义对象，程序会直接报错。解决办法是往元组中间插一个递增的计数器当第二项。

```python
count = 0
heapq.heappush(heap, (priority, count, item))
count += 1
```

## 两个核心模板

### 模板一，大小为 k 的堆

```python
heap = []
for x in 数据:
    heapq.heappush(heap, x)
    if len(heap) > k:
        heapq.heappop(heap)
```

堆里始终只留最大的 k 个，堆顶是这 k 个里最小的，也就是「进不来」的门槛值。215 和 347 都建立在这个模板上。

方向记法是，求第 k 大用最小堆，求第 k 小用最大堆。看起来反着，其实是因为堆顶的角色是「要被淘汰的那个」。

### 模板二，双堆

```python
self.small = []      # 最大堆，存负数，装较小的一半
self.large = []      # 最小堆，装较大的一半
```

要维持两条不变量。

- 大小平衡，两边个数之差最多是 1
- 顺序正确，small 里的所有数都小于等于 large 里的所有数

295 题用这个模板动态维护中位数。

## Hot 100 三道题

### 215. 数组中的第 K 个最大元素

```python
import heapq

def findKthLargest(nums, k):
    heap = []

    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)

    return heap[0]
```

- 完全就是模板一，堆里留最大的 k 个，堆顶就是第 k 大
- 用最小堆而不是最大堆，因为要淘汰的是这 k 个里最小的那个
- 注意第 k 大指的是排序后的位置，重复数字各占一个位置。`[3, 3, 3, 3]` 配 `k = 2` 答案是 3
- 易错：容量判断写成 `>= k`，放满 k 个就开始弹，最后堆里只剩 1 个
- 易错：返回写成 `heappop(heap)`，查询不该改动结构
- 复杂度 O(n log k)，比排序的 O(n log n) 好，k 越小时优势越明显

### 347. 前 K 个高频元素

```python
import heapq
from collections import Counter

def topKFrequent(nums, k):
    count = Counter(nums)
    heap = []

    for num, freq in count.items():
        heapq.heappush(heap, (freq, num))
        if len(heap) > k:
            heapq.heappop(heap)

    return [num for freq, num in heap]
```

- 先用哈希表统计频率，把比较依据从数值换成次数，之后就套模板一
- 元组写成 `(freq, num)`，次数放第一位，堆才会按次数排序
- 题目不要求返回顺序，不用再排序
- 易错：元组写成 `(num, freq)`，堆按数字大小排，答案完全错
- 易错：返回时只写 `return heap`，返回的是一堆元组
- 复杂度 O(n log k)

### 295. 数据流的中位数

```python
import heapq

class MedianFinder:
    def __init__(self):
        self.small = []      # 最大堆，存负数，装较小的一半
        self.large = []      # 最小堆，装较大的一半

    def addNum(self, num):
        heapq.heappush(self.small, -num)
        heapq.heappush(self.large, -heapq.heappop(self.small))
        if len(self.large) > len(self.small):
            heapq.heappush(self.small, -heapq.heappop(self.large))

    def findMedian(self):
        if len(self.small) > len(self.large):
            return -self.small[0]
        return (-self.small[0] + self.large[0]) / 2
```

- 中位数只依赖两个值，左半边的最大值和右半边的最小值，所以用两个堆各管一个
- `addNum` 的三步不能颠倒，先无脑放进左边，再把左边的最大值筛到右边，最后补平衡
- `findMedian` 里左边多一个说明总数是奇数，直接返回左堆顶。两边相等就取平均
- 易错：`small` 里存了负数，取值时忘记再取负
- 易错：漏掉最后一步平衡，两个堆越差越多，堆顶就不在中间了
- 复杂度，`addNum` 是 O(log n)，`findMedian` 是 O(1)

## 三题总表

| 题号 | 堆里存什么 | 堆的类型 | 堆顶的含义 | 时间 |
| --- | --- | --- | --- | --- |
| 215 第 K 大 | 数值 | 最小堆 | k 个候选里最小的那个 | O(n log k) |
| 347 前 K 高频 | (次数, 数字) | 最小堆 | k 个候选里次数最少的 | O(n log k) |
| 295 中位数 | 两个堆，数据分成两半 | 最大堆加最小堆 | 中间的那两个边界值 | addNum O(log n)，findMedian O(1) |

## 常见易错点

第一，`heap[0]` 之外的元素没有顺序。`heap[1]` 和 `heap[2]` 之间没有大小关系，要按顺序取只能靠反复 `heappop`。

第二，想用最大堆却直接 `heappush` 正数。Python 只有最小堆，必须存负数，取出来时再取负。

第三，`heapify` 是原地修改，会打乱原列表的顺序。需要保留原顺序就先复制一份。

第四，`heapreplace` 用在空堆上会报错。

第五，元组进堆时第二项不可比较，比如放了列表或者字典。

第六，容量判断写成 `>= k`。模板一里必须写 `> k`，放进去超了才弹。

第七，双堆漏掉平衡调整，两个堆的大小会越差越多，堆顶就不在中间了。

## 共同规律

这三道题分成两类。

第一类是「前 k 个」，215 和 347 属于这一类。共同骨架就是模板一，循环里放进去，超了就把最小的弹掉。区别只在比较依据，215 比数值本身，347 比出现次数。

判断信号是一个固定搭配。题目里出现「第 k 大」「前 k 个」这样的字眼，先想想能不能用一个大小为 k 的堆。

第二类是「动态维护某个统计量」，295 属于这一类。思路是先想清楚这个统计量依赖哪几个值，然后为每个值配一个堆。中位数依赖两个边界值，所以就配了两个堆。

还有一句关于堆顶的话值得记住。堆顶永远是「当前最该被淘汰的那个」，不是「最终想要的那个」。求最大的 k 个时，堆顶是这批里最小的，它是门槛。求中位数时，两个堆顶是中间的边界。把这个角色想清楚，用最小堆还是最大堆就不会选错。

最后是复杂度的标准说法。每次堆操作是 O(log n) 或者 O(log k)，总共做 n 次，所以整体是 O(n log n) 或者 O(n log k)。空间就是堆的大小。
