## 一句话概括

贪心是每一步都选当前看起来最好的那个，选完就不改。它不给后面的选择留余地，指望每一步的局部最优能堆出全局最优。代码通常很短，难点在于证明这个选择是安全的。

## 什么时候用它

看到下面这些信号，先想想贪心。

- 问最值，比如最大收益、最少步数、最多能分成几段
- 每一步有个明显的「越怎么样越好」，比如越早结束越好、越小越好
- 数据规模大，O(n^2) 会超时，暗示需要一次线性扫描
- 每一步的选择看起来可以独立决定，不用管后面的情况
- 找到了一个动态规划写法，但状态能压缩成一两个变量

反过来说，如果这一步的选择会改变后面能选的集合，而且这个改变不好处理，就该考虑动态规划。零钱兑换是典型例子，面额 1、3、4 去凑 6，贪心先拿 4 会多花一枚硬币，最优是 3 加 3。

## 贪心和动态规划的区别

| 对比项 | 贪心 | 动态规划 |
| --- | --- | --- |
| 保留多少状态 | 只保留一个当前最优 | 保留所有可能的状态 |
| 是否回头 | 不回头，选了就定了 | 从小规模的最优解一步步推 |
| 关键要求 | 局部最优能推出全局最优 | 有最优子结构和重叠子问题 |
| 是否需要证明 | 需要 | 转移写对就行 |
| 常见复杂度 | O(n) 或者 O(n log n) | 通常是 O(n^2) 或者更高 |
| 典型味道 | 敢丢 | 不遗漏 |

很多题两种写法都有，贪心常常是这个动态规划在状态能压缩时得到的加速版。121 题就是这种情况，动态规划的状态压到只剩一个最低价，压完就是贪心。状态压不下去的时候，比如同时要记住背包容量和当前物品，贪心一般就不成立。

## 怎么判断贪心成立

核心问题只有一个，这一步丢掉的那些选项，凭什么以后也用不上。这句话讲得通，贪心基本就站得住。

常用的证明方式有三种。

- 交换论证。假设存在一个最优解，它和贪心解在第一步不同，把最优解的第一步换成贪心的选择，证明结果不会变差。这是最常用的方式，这四道题都能用它
- 归纳法。假设前 i 步按贪心走仍然能推出最优解，再证第 i+1 步也成立
- 反证法。假设贪心解不是最优，推出矛盾

面试里不需要写完整证明，但心里要能说清这几句。

## Python 基础

### 常用到的几行

贪心没有专门的库，代码骨架就是一次遍历加几个变量。常出现的内置写法有这几个。

```python
best = max(best, price - min_price)   # 用 max 更新历史最优
reach = max(reach, i + num)           # 用 max 把边界往右推
for i, ch in enumerate(s):            # 同时拿到下标和值
    last[ch] = i                      # 字典记录最后出现的位置
```

求最小值时把 max 换成 min。两个函数都支持多个参数，也可以传一个可迭代对象。

### 初始值怎么定

贪心题最容易在初始值上出错，几种常见情况整理如下。

| 想要的东西 | 初始值 | 例子 |
| --- | --- | --- |
| 求最大收益，收益不能为负 | `0` | 121 的 best |
| 求最小值，数据可能很大 | `float('inf')` | 通用写法 |
| 求最大值，数据可能很小 | `float('-inf')` | 通用写法 |
| 用第一个元素当基准 | `nums[0]` | 121 的 min_price |
| 求最远可达位置 | `0` | 55 的 reach |

`float('inf')` 和 `float('-inf')` 参与比较时不会被误判，比随便写一个大数更可靠。

### 循环范围的三种写法

- `for i in range(n)` 适合每个下标都要判断的场景，比如 55 需要在下标越界时提前返回
- `for i in range(n - 1)` 适合最后一位不需要处理的场景，45 就是典型，从终点出发没有意义
- `for i, x in enumerate(nums)` 适合同时要下标和值，读起来最顺

## 两个核心模板

### 模板一，边扫描边维护最优值

```python
best = 初始值
for x in 数据:
    best = max(best, 由 x 算出来的候选值)
    # 顺手更新后面要用的辅助变量
```

适合求最大收益、最小代价这类题。变量一般是「到目前为止的最优结果」和「到目前为止最有利的某个量」。121 就是它，一个变量记历史最低价，一个变量记历史最大收益。

### 模板二，维护一个只往右走的边界

```python
bound = 0
for i, x in enumerate(数据):
    if 不符合条件:
        return 失败
    bound = max(bound, i + x)
```

适合覆盖、跳跃、切分区间这类题，共同点是可控或者可达的范围一定是一段连续区间，右端点只会往右走。这个模板有三种变形。

- 单边界判断断裂。55 用 reach 表示最远可达下标，下标超过它就说明断了
- 双边界数层数。45 用 end 表示当前这一跳的边界，farthest 表示下一跳的边界，下标追上 end 时结算一跳
- 单边界判断封闭。763 用 end 表示当前段必须延伸到的最远处，下标追上 end 时切一段

为什么这类题的区间一定连续。因为从一个位置能跳 k 步，就能跳 1 到 k 步中的任意一个，所以不会跳过中间的位置。

## Hot 100 四道题

### 121. 买卖股票的最佳时机

```python
def maxProfit(prices):
    min_price = prices[0]   # 到目前为止见过的最低价
    best = 0                # 到目前为止的最大收益

    for price in prices:
        best = max(best, price - min_price)   # 先假设今天卖出
        min_price = min(min_price, price)     # 再把今天纳入最低价

    return best
```

- 结论是每天问同一个问题，如果今天卖出，买入就该选之前的最低价
- 卖出日固定时，最优买入日是唯一确定的，所以不用枚举所有组合，一遍扫描就够
- 两句话必须按顺序执行。先算收益，再把今天纳入最低价。这题两种顺序结果一样，但顺序写对更稳妥
- 易错：min_price 初始值写成 0。这样第一天算出的收益会变成 prices[0] 本身，答案直接错
- 易错：best 初始值写成负无穷。题目要求赚不到钱就返回 0，从 0 开始能自动兜住
- 复杂度 O(n) 时间，O(1) 空间

### 55. 跳跃游戏

```python
def canJump(nums):
    reach = 0

    for i, num in enumerate(nums):
        if i > reach:                 # 这一格踩不到，后面的更踩不到
            return False
        reach = max(reach, i + num)   # 用这一格把边界往右推

    return True
```

- 关键观察是能到达的位置永远是从下标 0 开始的一段连续区间，所以用一个右端点就能描述整个可达集合
- 证明只要一句。如果位置 i 可达，那么 i 之前的任意位置也一定可达，因为那条路径上总有一个点一步就能跳过去
- 易错：忘记判断 `i > reach`，无脑更新边界。对 [3, 2, 1, 0, 4] 会错判成 True
- 易错：边界写成 `i >= reach`。i 等于 reach 时这一格是可以踩到的，相等要放行
- 易错：想模拟一条固定路径，比如每次都跳最远。对 [3, 3, 1, 0, 5] 会错，跳最远落在 0 上卡死，跳 1 步再跳 3 步反而能到终点
- 复杂度 O(n) 时间，O(1) 空间

### 45. 跳跃游戏 II

```python
def jump(nums):
    n = len(nums)
    jumps = 0        # 已经用掉几跳
    end = 0          # 当前这一跳能覆盖的最右下标
    farthest = 0     # 下一跳能覆盖到的最右下标

    for i in range(n - 1):
        farthest = max(farthest, i + nums[i])
        if i == end:     # 当前这一层走完，结算一跳
            jumps += 1
            end = farthest

    return jumps
```

- 这题本质是 BFS。第 k 层是走 k 跳能到达的下标集合，层与层依次往右推进，所以层数就是最少跳跃次数
- 因为每一层也是一段连续区间，BFS 可以压成两个变量，不用队列
- end 是已经结算过的区域有多远，farthest 是再结算一次能到多远，两个含义不能混
- 易错：循环范围写成 `range(n)`。这样会在终点上再结算一跳，答案多 1
- 易错：先判断 `i == end` 再更新 farthest。结算时用的是陈旧值，边界推不动，答案偏小
- 注意这题保证一定能到达终点，所以没有 55 那种断裂判断。反过来把这份代码拿去解 55 会错
- 复杂度 O(n) 时间，O(1) 空间

### 763. 划分字母区间

```python
def partitionLabels(s):
    # 第一遍，记录每个字符最后出现的下标
    last = {}
    for i, ch in enumerate(s):
        last[ch] = i

    result = []
    start = 0
    end = 0

    # 第二遍，一边扫描一边扩张边界
    for i, ch in enumerate(s):
        end = max(end, last[ch])
        if i == end:     # 这一段里的字符都不在后面出现，可以切了
            result.append(i - start + 1)
            start = i + 1

    return result
```

- 核心转化是把「这个字符后面还会不会出现」换成「这个字符最后出现在哪里」，前者要反复搜索，后者扫一遍就能全部拿到
- 一段能切开的条件是，这一段里所有字符的最后出现位置都不超过边界
- 正确性的讲法。切在 end 之前会不合法，因为最后出现位置在 end 的字符会跨两段。切在 end 处是安全的，所以最早能切的位置就是 end
- 易错：省掉第一遍扫描，直接在循环里用 `s.rfind(ch)`，复杂度退化成 O(n^2)
- 易错：end 更新写成 `end = last[ch]`，边界会往回退。必须取 max
- 易错：长度写成 `end - start`。两端都算在内，应该是 `end - start + 1`
- 复杂度 O(n) 时间，O(1) 空间，字典最多 26 项

## 四题总表

| 题号 | 维护的变量 | 变量的含义 | 结算时机 | 时间 | 空间 |
| --- | --- | --- | --- | --- | --- |
| 121 买卖股票 | min_price、best | 历史最低价，历史最大收益 | 每天先算收益，再更新最低价 | O(n) | O(1) |
| 55 跳跃游戏 | reach | 目前最远可达的下标 | 下标超过 reach 就失败 | O(n) | O(1) |
| 45 跳跃游戏 II | end、farthest | 当前跳的边界，下一跳的边界 | 下标追上 end 时跳数加一 | O(n) | O(1) |
| 763 划分字母区间 | last 表、start、end | 最后出现位置，段起点，段边界 | 下标追上 end 时切一段 | O(n) | O(1) |

763 的空间里，last 字典最多 26 项，和字符串长度无关，所以算 O(1)。

## 常见易错点

第一，不判断就套贪心。代码短，看不出毛病，提交就被反例打回来。写完先构造小规模反例，从两个元素、三个元素的例子开始试。

第二，初始值随便写。121 的 min_price 写成 0 会直接错，这类问题在空数组和单元素用例上最容易暴露。

第三，边界判断的符号写反。55 里必须写 `i > reach`，写成 `i >= reach` 会把正好落在边界上的位置当成不可达。

第四，更新顺序写反。121 要先把今天的收益算出来再更新最低价，45 要先把 farthest 更新好再结算跳数。两处反了都会出错，而且不一定报错。

第五，循环范围多算一步。45 的循环必须是 `range(n - 1)`，走到终点就该停。

第六，把贪心想成模拟一条路径。55 那题用 [3, 3, 1, 0, 5] 试一下就能看出来，跳最远的那条路反而走不通。

第七，用重复遍历代替一次预处理。763 里如果不用 last 表而每次都搜一遍，答案对但是会超时。

第八，混用题目给的保证。45 保证一定可达，55 不保证。两题的代码不能互换。

第九，返回值弄错。121 要返回收益这个数字，55 要返回布尔值，45 要返回步数，763 要返回长度列表。

## 共同规律

这四道题的代码都很短，全是一个 for 循环加两三个变量，复杂度都是 O(n) 时间和 O(1) 空间。它们的差别在变量管什么。

可以分成两类。

第一类是维护一个极值，121 属于这一类。它把问题拆成「每天问一遍同样的问题」，然后只记住最好的那个答案。写的时候要看两件事，历史最优怎么更新，辅助变量在什么时候刷新。

第二类是维护一个边界，55、45、763 都属于这一类。它们的共同前提是，可控或者可达的范围永远是一段连续区间，右端点只会往右走。写的时候要把三件事想清楚，边界代表什么、什么时候该结算、结算之后边界换成谁。

边界这一类内部又有细微差别。55 只要一个边界，判断的是有没有断裂。45 要两个边界，一个管当前这一跳，一个管下一跳，靠两者之间的一追一赶来数层数。763 也用一个边界，但它多了 start 来记录段的起点，用来算长度。

正确性的证明基本都是交换论证，写法可以统一成一句话。假设最优解在这一步选了别的，把它换成贪心的选择，答案不会变差。

判断信号可以这样记。

- 问最大收益，并且每天的最优买卖可以独立计算，想 121 这类
- 问能不能到达、最少几步，并且每一步的下一步范围由当前位置和数值共同决定，先想 BFS 分层，再看能不能压成一两个变量
- 出现划分、分段、同类元素必须待在一起这类描述，先想为每个元素记录位置信息，再看边界扩张

还有一句关于顺序的话值得记。贪心题里变量的更新顺序经常是有讲究的，先算候选值再更新辅助变量，还是先更新辅助变量再结算，取决于这一步用的是旧值还是新值。写完之后往回读一遍，确认每个变量用的都是该用的那一版。
